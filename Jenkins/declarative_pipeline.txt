# 1. Complete Jenkins Pipeline (Real DevOps Example)

```groovy
pipeline {

    agent any

    triggers {
        pollSCM('H/5 * * * *')
    }

    environment {
        APP_NAME = "payment-service"
        DOCKER_REPO = "nikhilsy/payment-service"
        SONAR_SERVER = "sonarqube-server"
    }

    stages {

        stage('Checkout Code') {
            steps {
                checkout([
                    $class: 'GitSCM',
                    branches: [[name: '*/main']],
                    userRemoteConfigs: [[
                        url: 'https://github.com/example/payment-service.git'
                    ]]
                ])
            }
        }

        stage('Build') {
            steps {
                retry(3) {
                    sh 'mvn clean package'
                }
            }
        }

        stage('Tests and Scan') {

            parallel {

                stage('Unit Tests') {
                    steps {
                        sh 'mvn test'
                    }
                }

                stage('SonarQube Scan') {
                    steps {
                        sh 'mvn sonar:sonar'
                    }
                }

            }
        }

        stage('Build Docker Image') {
            steps {
                sh """
                docker build -t ${DOCKER_REPO}:${BUILD_NUMBER} .
                """
            }
        }

        stage('Push Docker Image') {
            steps {
                sh """
                docker push ${DOCKER_REPO}:${BUILD_NUMBER}
                """
            }
        }

        stage('Approval') {
            steps {
                input message: "Approve deployment to Kubernetes?"
            }
        }

        stage('Deploy to Kubernetes') {
            steps {
                sh """
                kubectl set image deployment/${APP_NAME} \
                ${APP_NAME}=${DOCKER_REPO}:${BUILD_NUMBER}
                """
            }
        }
    }

    post {

        always {
            echo "Pipeline execution completed"
        }

        success {
            echo "Deployment successful"
        }

        failure {
            echo "Pipeline failed"
        }
    }
}
```


Meaning:

```

```

```

agent3 (kubernetes)
```

# 3.3 `triggers`

```
triggers {
    pollSCM('H/5 * * * *')
}
```

This tells Jenkins to check Git repo every **5 minutes**.

Cron format:

```
H/5 * * * *
```

Meaning:

```
Every 5 minutes check if Git repo changed
```

If new commit is detected → pipeline triggers.

```

```

Command:

```

sh 'mvn clean package'
}
```

Explanation

### `retry(3)`

If build fails Jenkins retries **3 times**.

Example

```
1st build → fail
2nd build → fail
3rd build → success
```

This helps when failure happens due to:

```
Network issue
Maven dependency timeout
Temporary error
```

```

```

Meaning

| Command | Purpose          |
| ------- | ---------------- |
| clean   | remove old build |
| package | create JAR/WAR   |

```

```

# 12. Why `retry(3)` Works Without `options`

You asked a **very good question**.

There are **two retry mechanisms in Jenkins**.

---

### 1. Step Retry

```
retry(3) {
sh 'mvn clean package'
}
```

This is a **pipeline step**.

Meaning:

```
Retry this block 3 times
```

This does **not require `options`**.

---

### 2. Pipeline Retry (options block)

```
options {
retry(3)
}
```

This retries **entire pipeline**.

Example

```
pipeline fails
Jenkins reruns entire pipeline
```

---

# Difference

| Type          | Scope                    |
| ------------- | ------------------------ |
| retry step    | retries specific command |
| options retry | retries full pipeline    |

# 14. Very Important DevOps Interview Questions

### Q1 Why run tests and scan in parallel?

To **reduce pipeline execution time**.

---

### Q2 Why use BUILD_NUMBER in Docker tag?

Ensures **unique image version for each build**.

---

### Q3 Why use manual approval?

Prevents **automatic production deployment**.

### Q4 Why retry Maven build?

Network failures while downloading dependencies.
