# 1. What is AWS X-Ray?

### Definition

**AWS X-Ray** is a **distributed tracing service** used to **analyze, debug, and monitor applications—especially microservices architectures**.

---

### Simple Meaning

```text
X-Ray = Request Tracking Tool
```

It helps you **trace a request end-to-end across multiple services**.

---

# 2. Why AWS X-Ray?

### Problem Without X-Ray

```text
User → API → Service A → Service B → DB
```

If something is slow or fails:

```text
❌ Hard to know where problem is
```

---

### Solution With X-Ray

```text
User → API → Service A → Service B → DB
           ↓
        X-Ray traces everything
```

You can see:

* Which service is slow
* Where error happened
* Total request time

---

# 3. Key Concepts

---

## 3.1 Trace

### Definition

A **trace** represents the **entire journey of a request**.

---

### Example

```text
User request → API → Lambda → DB
```

This full path = **Trace**

---

## 3.2 Segment

### Definition

A **segment** is a **part of a trace generated by a service**.

---

### Example

```text
API Gateway → Segment 1
Lambda → Segment 2
DynamoDB → Segment 3
```

---

## 3.3 Subsegment

### Definition

A **subsegment** is a **detailed breakdown inside a segment**.

---

### Example

```text
Lambda
   ├── Call DB
   ├── Call external API
   └── Process data
```

---

## 3.4 Service Map

### Definition

Visual representation of all services and their interactions.

---

### Example

```text
API Gateway → Lambda → DynamoDB
                  ↓
               S3
```

---

# 4. How AWS X-Ray Works

```text
Application receives request
        ↓
X-Ray SDK adds trace ID
        ↓
Each service creates segment
        ↓
Data sent to X-Ray daemon
        ↓
Stored in X-Ray service
        ↓
Visualized in console
```

# 9. Sampling

### Definition

X-Ray does not trace every request to reduce cost.

---

### Example

```text
1000 requests → only 100 traced
```

---

### Why?

```text
Reduce cost
Improve performance
```
