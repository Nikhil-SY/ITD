# 🔹 1. What is SonarQube (Deep Understanding)

👉 **SonarQube = Static Code Analysis Platform**

### 🔸 “Static Code Analysis” means:

* Code is analyzed **without executing it**
* Detects issues early in CI/CD

---

# 🔹 2. Core Terminologies (VERY IMPORTANT)

---

## 🔸 1. Project

👉 A project in SonarQube = **your application codebase**

Example:

```
my-payment-service
```

---

## 🔸 2. `sonar.projectKey`

👉 Unique identifier for project

```properties
sonar.projectKey=my-app
```

* Must be **unique in SonarQube**
* Used internally to track history

---

## 🔸 3. `sonar.projectName`

👉 Human-readable name

```properties
sonar.projectName=My Application
```

---

## 🔸 4. `sonar.sources`

👉 Path of source code to scan

```properties
sonar.sources=src
```

* `.` → current directory
* Can specify multiple folders

---

## 🔸 5. Sonar Scanner

👉 Tool that:

* Reads your code
* Sends it to SonarQube server

Types:

* CLI scanner
* Maven plugin (`mvn sonar:sonar`)
* Gradle plugin

---

## 🔸 6. SonarQube Server

👉 Core engine that:

* Processes analysis
* Stores results
* Provides UI dashboard

---

## 🔸 7. Database

👉 Stores:

* Analysis results
* History
* Metrics

⚠️ Production:

* Use PostgreSQL
  ❌ Not H2 (default)

---

## 🔸 8. Metrics (Key Concept)

👉 Quantitative measurements

Examples:

* Lines of Code
* Code Coverage
* Duplications

---

## 🔸 9. Issues (Most Important)

👉 Problems found in code

Types:

| Type          | Meaning        |
| ------------- | -------------- |
| Bug           | Logic error    |
| Vulnerability | Security issue |
| Code Smell    | Bad practice   |

---

## 🔸 10. Severity Levels

* Blocker
* Critical
* Major
* Minor
* Info

---

## 🔸 11. Code Smell

👉 Not a bug, but poor coding practice

Example:

```java
if (a == true)   // unnecessary
```

---

## 🔸 12. Technical Debt

👉 Effort required to fix issues

Example:

* “2 days to fix all smells”

---

## 🔸 13. Quality Profile

👉 Set of rules applied during analysis

Example:

* Java profile
* Custom rules

---

## 🔸 14. Quality Gate (CRITICAL)

👉 Conditions to pass/fail build

Example:

* Coverage > 80%
* No critical bugs

---

## 🔸 15. Quality Gate Status

* ✅ Passed
* ❌ Failed

---

## 🔸 16. Coverage

👉 % of code tested by unit tests

---

## 🔸 17. Duplications

👉 Repeated code blocks

---

## 🔸 18. Webhook

👉 SonarQube → Jenkins communication

Used to:

* Send Quality Gate result

---

## 🔸 19. Token

👉 Authentication key

Used by Jenkins to:

* Connect to SonarQube securely

---

# 🔹 3. Jenkins Integration Terms (Deep)

---

## 🔸 1. Jenkins Pipeline

👉 CI/CD workflow defined in code

---

## 🔸 2. `withSonarQubeEnv`

```groovy
withSonarQubeEnv('sonarqube')
```

👉 Injects:

* Sonar URL
* Token
* Environment variables

---

## 🔸 3. `mvn sonar:sonar`

👉 Triggers scan using Maven plugin

---

## 🔸 4. `waitForQualityGate`

```groovy
waitForQualityGate abortPipeline: true
```

👉 Waits for result from SonarQube

* If fail → pipeline stops

---

## 🔸 5. SonarQube Scanner Tool (Jenkins)

👉 Installed tool used by pipeline

---

# 🔹 4. End-to-End Flow (Very Important)

```text
1. Developer pushes code
2. Jenkins triggers pipeline
3. Code is built (mvn install)
4. Sonar Scanner runs
5. Code sent to SonarQube
6. Analysis happens
7. Results stored in DB
8. Quality Gate evaluated
9. Webhook notifies Jenkins
10. Pipeline passes/fails
```

---

# 🔹 5. Real Example Breakdown

```properties
sonar.projectKey=payment-service
sonar.sources=src
sonar.java.binaries=target/classes
```

👉 Meaning:

* Identify project
* Scan source folder
* Use compiled classes for analysis

# 🔹 6. Common Confusions (Interview Gold)

---

### ❓ Scanner vs Server

| Scanner    | Server        |
| ---------- | ------------- |
| Sends code | Analyzes code |

---

### ❓ Build vs Analysis

* Build → compile code
* Analysis → check quality

---

### ❓ Quality Gate vs Quality Profile

| Feature | Purpose   |
| ------- | --------- |
| Profile | Rules     |
| Gate    | Pass/Fail |

---

# 🔹 7. Real-world DevOps Flow

```text
GitHub → Jenkins → Build → SonarQube → Quality Gate → Deploy
```

👉 Deployment happens only if:

* Quality Gate passes

---

# 🔚 Final One-Liner

👉 *SonarQube analyzes code quality using rules and metrics, and Jenkins enforces it in CI/CD pipelines using quality gates.*
