# 🐳 Docker Compose – Detailed Explanation

## ✅ What is Docker Compose?

Docker Compose is a tool used to:
👉 **Define and run multi-container Docker applications**

Instead of running multiple `docker run` commands, you define everything in a **single YAML file (`docker-compose.yml`)**

---

## ❓ Why Docker Compose?

### 🚨 Problem (Without Compose)

Running multiple containers manually:

```bash
docker run -d --name db -e MYSQL_ROOT_PASSWORD=pass mysql
docker run -d --name app -p 8080:8080 myapp
```

❌ Issues:

* Hard to manage
* No dependency handling
* No central configuration

---

### 💡 Solution (Docker Compose)

👉 Use one YAML file to manage everything

✅ Benefits:

* One command to start/stop
* Easy configuration
* Handles networking automatically
* Good for local development & testing

---

# ⚙️ How Docker Compose Works

1. Define services in `docker-compose.yml`
2. Run:

```bash
docker compose up
```

3. Docker:

   * Creates network
   * Starts containers
   * Links services

---

# 🔹 Basic Structure of `docker-compose.yml`

```yaml
version: "3"

services:
  app:
    image: myapp
    ports:
      - "8080:8080"

  db:
    image: mysql
    environment:
      MYSQL_ROOT_PASSWORD: pass
```

---

## 📌 Key Fields

### 🔸 `version`

* Compose file version

---

### 🔸 `services`

* Defines containers

---

### 🔸 `image`

* Docker image to use

---

### 🔸 `build`

* Build image from Dockerfile

---

### 🔸 `ports`

```yaml
ports:
  - "8080:80"
```

👉 Host → Container

---

### 🔸 `environment`

```yaml
environment:
  MYSQL_ROOT_PASSWORD: pass
```

---

### 🔸 `volumes`

```yaml
volumes:
  - myvol:/data
```

---

### 🔸 `depends_on`

```yaml
depends_on:
  - db
```

👉 Ensures db starts before app

---

### 🔸 `networks`

* Custom network configuration

---

# 🔥 Example 1: Web App + MySQL

```yaml
version: "3"

services:
  app:
    image: nginx
    ports:
      - "8080:80"
    depends_on:
      - db

  db:
    image: mysql
    environment:
      MYSQL_ROOT_PASSWORD: pass
    volumes:
      - db-data:/var/lib/mysql

volumes:
  db-data:
```

---

## 📌 What happens?

1. Creates **2 containers**
2. Creates **default network**
3. App can access DB using:

```bash
db:3306
```

👉 Docker provides **automatic DNS**

---

# 🔹 Example 2: Build + Run App

```yaml
version: "3"

services:
  app:
    build: .
    ports:
      - "5000:5000"
```

---

👉 Docker will:

* Build image from Dockerfile
* Run container

# 🔹 Networking in Docker Compose

👉 By default:

* Creates a network like:

```bash
projectname_default
```

👉 Services communicate using:

```bash
http://service-name
```

Example:

```bash
http://db:3306
```

# 🔹 Docker Compose vs Docker Run

| Feature         | Docker Run  | Docker Compose |
| --------------- | ----------- | -------------- |
| Multi-container | ❌ Hard      | ✅ Easy         |
| Configuration   | CLI         | YAML           |
| Networking      | Manual      | Automatic      |
| Use Case        | Simple apps | Complex apps   |

# 🔹 Best Practices

* Use `.env` file for secrets
* Use named volumes
* Avoid hardcoding passwords
* Use `depends_on` properly

---

# 🔹 Common Mistakes

❌ Forgetting ports → app not accessible
❌ Wrong indentation in YAML
❌ Not using volumes → data loss

# 🔹 Short Interview Answer

**Q: What is Docker Compose?**

👉 Docker Compose is a tool used to define and manage multi-container Docker applications using a YAML file, allowing you to start all services with a single command.
