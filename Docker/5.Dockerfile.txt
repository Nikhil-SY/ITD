# 🔹 1. `FROM` (Base Image)

### ✅ What it does:

* Defines the **starting point (base OS image)**

### ⏱️ Runs:

* Build time

### 📌 Example:

```dockerfile
FROM ubuntu:20.04
```

### 🧠 Deep Understanding:

* Pulls image from registry
* All next instructions build **on top of this layer**

### 🔥 Interview Point:

👉 Without `FROM`, Dockerfile is invalid

---

# 🔹 2. `RUN` (Execute Commands)

### ✅ What it does:

* Runs commands **inside image during build**

### ⏱️ Runs:

* Build time

### 📌 Example:

```dockerfile
RUN apt-get update && apt-get install -y nginx
```

### 🧠 Deep Understanding:

* Each `RUN` creates a **new layer**
* Runs inside a **temporary container**, then saved as image layer

### ⚠️ Important:

```dockerfile
RUN apt-get update
RUN apt-get install -y nginx
```

❌ Creates 2 layers (inefficient)

✔ Better:

```dockerfile
RUN apt-get update && apt-get install -y nginx
```

### 🔥 Interview Point:

👉 Used for **installing packages & dependencies**

---

# 🔹 3. `COPY` (Local → Container)

### ✅ What it does:

* Copies files from **host → image**

### ⏱️ Runs:

* Build time

### 📌 Example:

```dockerfile
COPY . /app
```

### 🧠 Deep Understanding:

* Copies everything from current directory
* Uses `.dockerignore`

### 🔥 Interview Point:

👉 Preferred over `ADD` (simple & predictable)

---

# 🔹 4. `ADD` (Advanced Copy)

### ✅ What it does:

* Same as COPY + extra features

### 📌 Example:

```dockerfile
ADD https://example.com/file.zip /app
ADD app.tar.gz /app
```

### 🧠 Extra Features:

* Downloads files from URL
* Auto-extracts `.tar.gz`

### ⚠️ Use Carefully:

👉 Can cause unexpected behavior

---

# 🔹 5. `WORKDIR` (Set Working Directory)

### ✅ What it does:

* Sets default directory for next commands

### 📌 Example:

```dockerfile
WORKDIR /app
```

### 🧠 Deep Understanding:

* Automatically creates directory if not exists
* Affects `RUN`, `CMD`, `ENTRYPOINT`

### 🔥 Interview Point:

👉 Replaces multiple `cd` commands

---

# 🔹 6. `CMD` (Default Command)

### ✅ What it does:

* Defines **default command when container starts**

### ⏱️ Runs:

* Runtime

### 📌 Example:

```dockerfile
CMD ["node", "app.js"]
```

### 🧠 Deep Understanding:

* Only ONE CMD allowed
* Can be overridden:

```bash
docker run myapp python app.py
```

### 🔥 Interview Point:

👉 Used for **default execution**

---

# 🔹 7. `ENTRYPOINT` (Main Command)

### ✅ What it does:

* Defines **fixed command**

### 📌 Example:

```dockerfile
ENTRYPOINT ["python"]
```

### 🧠 Deep Understanding:

* Cannot be easily overridden
* CMD acts as **arguments** to ENTRYPOINT

### 📌 Example:

```dockerfile
ENTRYPOINT ["python"]
CMD ["app.py"]
```

👉 Runs:

```bash
python app.py
```

---

# 🔹 8. `EXPOSE` (Port Documentation)

### ✅ What it does:

* Declares port container listens on

### 📌 Example:

```dockerfile
EXPOSE 80
```

### 🧠 Important:

❌ Does NOT open port
✔ Only documentation

---

# 🔹 9. `ENV` (Environment Variables)

### ✅ What it does:

* Sets environment variables

### 📌 Example:

```dockerfile
ENV NODE_ENV=production
```

### 🧠 Deep Understanding:

* Available in container runtime

---

# 🔹 10. `ARG` (Build-Time Variables)

### ✅ What it does:

* Variables used **during build only**

### 📌 Example:

```dockerfile
ARG VERSION=1.0
```

### 🧠 Difference from ENV:

| Feature    | ARG | ENV |
| ---------- | --- | --- |
| Build time | ✔   | ✔   |
| Runtime    | ❌   | ✔   |

---

# 🔹 11. `VOLUME` (Persistent Storage)

### ✅ What it does:

* Creates mount point

### 📌 Example:

```dockerfile
VOLUME /data
```

### 🧠 Deep Understanding:

* Data stored outside container lifecycle

---

# 🔹 12. `USER` (Run as User)

### ✅ What it does:

* Runs container as specific user

### 📌 Example:

```dockerfile
USER nginx
```

### 🔥 Interview Point:

👉 Improves security (avoid root)

---

# 🔹 13. `HEALTHCHECK`

### ✅ What it does:

* Checks container health

### 📌 Example:

```dockerfile
HEALTHCHECK CMD curl -f http://localhost || exit 1
```

### 🧠 Output:

* healthy
* unhealthy

---

# 🔹 14. `LABEL`

### ✅ What it does:

* Adds metadata

### 📌 Example:

```dockerfile
LABEL version="1.0"
```

---

# 🔹 15. `SHELL`

### ✅ What it does:

### ✅ What it does:



# 🔹 19. Build Command (Detailed Explanation)

```bash
docker build -t myapp:1.0 .
```

### 🔍 Breakdown:

* `docker build` → Build image
* `-t` → Tag image
* `myapp` → Image name
* `1.0` → Version
* `.` → Current directory (Dockerfile location)

---

### 🔄 What happens internally:

1. Docker reads Dockerfile
2. Executes each instruction
3. Creates layers
4. Caches layers
5. Builds final image

# 🔹 20. FINAL INTERVIEW SUMMARY

👉 **Dockerfile instructions are executed during build time to create image layers, except CMD and ENTRYPOINT which run at container runtime.**
