# 🐳 Multi-stage Docker Build

## ✅ What is Multi-stage Build?

Multi-stage build allows you to:
👉 Use **multiple `FROM` statements** in a single Dockerfile
👉 Create **intermediate build stages**
👉 Copy only required files to final image

---

## ❓ Why Multi-stage Build?

### 🚨 Problem (Without Multi-stage)

* Final image contains:

  * Build tools (Maven, Node, compilers)
  * Source code
  * Temporary files
    👉 Result:
* ❌ Large image size
* ❌ Security risks
* ❌ Slower deployments

---

### 💡 Solution (Multi-stage)

👉 Keep:

* Build tools → **only in build stage**
* Final image → **only runtime files**

✅ Benefits:

* Smaller image size
* Better security
* Faster CI/CD

---

# ⚙️ How Multi-stage Build Works

1. First stage → build application
2. Second stage → copy only required output
3. Final image → minimal runtime

---

# 🔹 Basic Syntax

```dockerfile
FROM <base-image> AS build-stage

# build steps

FROM <base-image> AS runtime-stage

# copy from previous stage
COPY --from=build-stage <source> <destination>
```

---

# 🔥 Example 1: Java (Maven) Application

## 📌 Without Multi-stage (Bad Practice)

```dockerfile
FROM maven:3.8-openjdk-17

WORKDIR /app
COPY . .
RUN mvn clean package

CMD ["java", "-jar", "target/app.jar"]
```

👉 Problem:

* Maven + source code included in final image

---

## ✅ With Multi-stage (Best Practice)

```dockerfile
# Stage 1: Build
FROM maven:3.8-openjdk-17 AS build

WORKDIR /app
COPY . .
RUN mvn clean package

# Stage 2: Runtime
FROM openjdk:17

WORKDIR /app
COPY --from=build /app/target/app.jar app.jar

CMD ["java", "-jar", "app.jar"]
```

---

### 📌 Flow

1. Stage 1:

   * Builds `.jar` file
2. Stage 2:

   * Copies only `.jar`
   * No Maven, no source code

---

### 🎯 Result

* Image size reduced significantly
* Cleaner and secure image

---

# 🔥 Example 2: Node.js Application

```dockerfile
# Stage 1: Build
FROM node:18 AS build

WORKDIR /app
COPY package*.json ./
RUN npm install

COPY . .
RUN npm run build

# Stage 2: Runtime
FROM nginx:alpine

COPY --from=build /app/build /usr/share/nginx/html
```

---

### 📌 Flow

* Node used only for build
* Final image uses lightweight nginx

---

# 🔹 Key Concepts

## 1️⃣ Stage Naming

```dockerfile
FROM node:18 AS build
```

👉 Helps in referencing:

```dockerfile
COPY --from=build
```

---

## 2️⃣ Copy Between Stages

```dockerfile
COPY --from=build /app/output /app
```

👉 Only required artifacts copied

---

## 3️⃣ Final Image

👉 Only last `FROM` is the final image

# 🔹 Real DevOps Scenario

## CI/CD Pipeline (Jenkins / GoCD)

1. Code pushed to Git
2. Pipeline triggers build
3. Docker multi-stage:

   * Stage 1 → build app
   * Stage 2 → create lightweight image
4. Push to Docker Hub
5. Deploy to Kubernetes

👉 Benefit:

* Faster deployments
* Lower storage cost

---

# 🔹 Best Practices

* Use **lightweight base images** (e.g., alpine)
* Minimize layers
* Use `.dockerignore`
* Keep final image minimal
* Avoid unnecessary tools in runtime stage

---

# 🔹 Common Mistakes

❌ Copying entire project in final stage
❌ Not using `.dockerignore`
❌ Using same heavy image in all stages

# 🔹 Short Interview Answer

**Q: What is multi-stage Docker build?**

👉 Multi-stage build allows using multiple stages in a Dockerfile, where build dependencies are kept in earlier stages and only the required artifacts are copied to the final image, resulting in a smaller and secure image.
