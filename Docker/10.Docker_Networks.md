# 🐳 Docker Networking – Detailed Explanation

## ✅ What is Docker Networking?

Docker networking allows **containers to communicate**:

* With **other containers**
* With the **host machine**
* With the **outside world (internet)**

Docker handles:

* IP address assignment
* DNS resolution (container name → IP)
* Network isolation

---

# 🔹 Types of Docker Networks

## 1️⃣ Bridge Network (Default)

### 📌 Definition

* Default network created by Docker
* Used when you run a container without specifying a network

### 📌 How it works

* Docker creates a virtual bridge: `docker0`
* Containers get private IPs
* NAT is used to access external network

### 📌 IP Assignment

* Range: usually `172.17.0.0/16`
* Each container gets a **unique private IP**
* Example:

  * Container1 → 172.17.0.2
  * Container2 → 172.17.0.3

---

### 📌 Example

```bash
docker run -d --name c1 nginx
docker run -d --name c2 nginx
```

Check IP:

```bash
docker inspect c1
```

---

### 📌 Communication

* Containers **cannot communicate using names** (default bridge)
* Need IP or custom bridge

---

### 📌 Custom Bridge Network (Recommended)

```bash
docker network create my-bridge
docker run -d --name c1 --network my-bridge nginx
docker run -d --name c2 --network my-bridge nginx
```

✅ Now:

* Containers can communicate using **names**

```bash
ping c2
```

---

## 2️⃣ Host Network

### 📌 Definition

* Container shares **host network directly**

### 📌 Key Point

* No separate IP for container

### 📌 IP Assignment

* Container uses **host IP**
* No NAT

---

### 📌 Example

```bash
docker run -d --network host nginx
```

---

### 📌 Behavior

* If nginx runs on port 80 → accessible via:

```
http://<host-ip>:80
```

---

### 📌 Use Case

* High performance apps
* No network isolation needed

---

## 3️⃣ None Network

### 📌 Definition

* Completely isolated network

### 📌 IP Assignment

* No IP assigned
* Only loopback interface (`127.0.0.1`)

---

### 📌 Example

```bash
docker run -d --network none nginx
```

---

### 📌 Use Case

* Security testing
* Isolated workloads

---

## 4️⃣ Overlay Network (Multi-host)

### 📌 Definition

* Used in **Docker Swarm / Kubernetes**
* Connects containers across multiple hosts

---

### 📌 IP Assignment

* Each container gets IP from overlay subnet
* Managed via distributed KV store

Example range:

```
10.0.0.0/24
```

---

### 📌 Example

```bash
docker network create -d overlay my-overlay
```

---

### 📌 Use Case

* Microservices architecture
* Multi-node clusters

---

## 5️⃣ Macvlan Network

### 📌 Definition

* Assigns **real IP from LAN network**
* Container behaves like a physical device

---

### 📌 IP Assignment

* From your local network (e.g., router DHCP)
* Example:

  * 192.168.1.100
  * 192.168.1.101

---

### 📌 Example

```bash
docker network create -d macvlan \
  --subnet=192.168.1.0/24 \
  --gateway=192.168.1.1 \
  -o parent=eth0 my-macvlan
```

---

### 📌 Use Case

* Legacy apps
* Need direct LAN access

---

# 🔹 Important Docker Network Commands

## 📌 List Networks

```bash
docker network ls
```

---

## 📌 Inspect Network

```bash
docker network inspect bridge
```

---

## 📌 Create Network

```bash
docker network create my-network
```

Custom subnet:

```bash
docker network create \
  --subnet 192.168.10.0/24 \
  my-network
```

---

## 📌 Connect Container to Network

```bash
docker network connect my-network c1
```

---

## 📌 Disconnect Container

```bash
docker network disconnect my-network c1
```

---

## 📌 Remove Network

```bash
docker network rm my-network
```

---

# 🔹 Port Mapping (Important)

### 📌 Why needed?

Bridge network uses private IP → not accessible externally

### 📌 Example

```bash
docker run -d -p 8080:80 nginx
```

Meaning:

```
Host:8080 → Container:80
```

---

# 🔹 DNS in Docker

* Docker provides **internal DNS**
* Works only in **custom bridge / overlay**

Example:

```bash
curl http://c2
```

# 🔹 Interview Tip Answer (Short)

**Q: How Docker assigns IP?**

👉 Docker uses:

* **Bridge:** Private subnet (172.x.x.x) via NAT
* **Host:** Uses host IP directly
* **Overlay:** Distributed subnet across nodes
* **Macvlan:** Real LAN IP
* **None:** No IP
