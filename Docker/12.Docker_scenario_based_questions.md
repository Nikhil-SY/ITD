cat /etc/docker/daemon.json

🐳 Explanation of Docker Service Restart Commands

🔁 1. sudo systemctl daemon-reexec

✅ What it does:

Re-executes the systemd process

Reloads systemd binary itself (not just configs)


🧠 Why we use it:

After systemd upgrade

If systemd is in a bad state

Rarely used in daily operations


👉 Think:

> “Restarting the system manager itself”




---

🔄 2. sudo systemctl daemon-reload

✅ What it does:

Reloads service configuration files

Reads updated .service files from:

/etc/systemd/system/
/lib/systemd/system/


🧠 When to use:

After modifying:

Docker service file

Any systemd unit file



👉 Without this:

Changes won’t be picked up ❌



---

▶️ 3. sudo systemctl restart docker

✅ What it does:

Stops and starts the Docker service


🧠 When to use:

After config changes

When Docker is not working

To apply new settings



---

🔗 Combined Flow (Why all 3 together?)

👉 When troubleshooting:

1. daemon-reexec
→ Refresh systemd itself


2. daemon-reload
→ Reload updated configs


3. restart docker
→ Apply changes to Docker




---

🎯 Simple Analogy

daemon-reexec → Restart OS service manager

daemon-reload → Re-read config files

restart docker → Restart the actual application



---

✅ Final Interview Answer

👉
“These commands are used to ensure Docker starts with the latest configuration.

daemon-reexec reinitializes systemd itself

daemon-reload reloads updated service configuration files

restart docker restarts the Docker service to apply changes”

🐳 Docker Container Restarting — Troubleshooting

✅ 1. Check Container Status

docker ps -a

Look for:

Restarting

Exit code

Container uptime



---

📜 2. Check Logs (First thing to do)

docker logs <container_id>

👉 This usually gives the exact reason:

App crash

Missing file

Port issue

Dependency failure



---

🔢 3. Check Exit Code

docker inspect <container_id> --format='{{.State.ExitCode}}'

Common Exit Codes:

0 → App finished → container stops → restart loop

1 → Application error

137 → Out Of Memory (OOMKilled)

127 → Command not found



---

⚙️ 4. Check CMD / ENTRYPOINT

docker inspect <container_id> | grep -i cmd

👉 Common issue:

Wrong command

Script not present

App exits immediately


Example problem:

CMD ["python", "app.py"]

If app.py is missing → container restarts


---

🧠 5. Check Resource Issues

docker stats

👉 If memory is high:

Container gets killed → restarts


Fix:

docker run -m 512m <image>

(or increase memory)


---

🌐 6. Check Port Conflicts

Error in logs:

Address already in use

Fix:

Change port mapping


docker run -p 8081:8080 <image>


---

🔁 7. Check Restart Policy

docker inspect <container_id> | grep RestartPolicy

Types:

always

on-failure

no


👉 If always → it keeps restarting even if app fails


---

🔐 8. Check File / Permission Issues

File not executable

Wrong path


Example:

permission denied

Fix:

chmod +x script.sh


---

🧪 9. Run Container in Interactive Mode (Best Debug Step)

docker run -it <image> /bin/sh

Then:

Check files (ls)

Run app manually


python app.py


---

🔗 10. Check Dependency Issues

DB not reachable

API down


Logs example:

Connection refused

🐳 docker run -m 1g <image> — Explanation

✅ What this command does

docker run -m 1g <image>

👉 It limits the container memory to 1 GB

-m = memory limit

1g = 1 gigabyte



---

🧠 Why we use it

Prevent a container from consuming all system memory

Avoid system crashes

Control resource usage in multi-container environments



---

⚙️ How it works internally

Docker uses Linux cgroups (control groups)

It enforces a hard memory limit on the container


👉 If container exceeds 1 GB:

Kernel sends SIGKILL (9)

Container stops

Exit Code = 137 (OOMKilled)



---

📊 Example

docker run -m 512m nginx

👉 Nginx container can use max 512 MB RAM


---

⚠️ Important Notes

1. Hard Limit

Container cannot exceed this limit



---

2. Without -m

Container can use unlimited memory (host dependent)



---

3. Combine with CPU limits

docker run -m 1g --cpus="1.5" <image>


---

🔁 Related Option

Swap Memory

docker run -m 1g --memory-swap=2g <image>

1 GB RAM + 1 GB swap



---

🎯 Final Interview Answer

👉
“docker run -m 1g sets a memory limit of 1 GB for the container using cgroups. If the container exceeds this limit, it is killed by the kernel with exit code 137. This helps in resource management and prevents a single container from exhausting system memory.”
