# Dynamic Provisioning with **AWS EBS CSI Driver** (Installation + What Every Command Does)

Since you use **AWS and Kubernetes**, this is the **real-world setup** for dynamic provisioning.

---

# 1. First: Why do we need EBS CSI Driver?

Kubernetes itself **cannot directly create AWS EBS volumes**.

It needs a **driver/plugin** to talk to AWS.

That plugin is:

**Amazon Elastic Block Store (EBS) CSI Driver**

Amazon EBS CSI Driver

Flow:

```text
PVC created
   ↓
Kubernetes sees StorageClass
   ↓
Calls EBS CSI Driver
   ↓
Driver calls AWS EC2 API
   ↓
Creates EBS volume
   ↓
Attaches volume to worker node
   ↓
Mounts volume inside Pod
```

Without EBS CSI driver:

❌ Kubernetes cannot dynamically create EBS disks.

---

# 2. Architecture of EBS CSI Driver (Very Important)

The driver usually runs in **two parts**:

## A. Controller Plugin

Usually runs as a **Deployment**.

Responsible for:

* Creating EBS volumes
* Deleting EBS volumes
* Resizing EBS volumes
* Attaching volumes to EC2 nodes
* Detaching volumes

Think:

```text
Control plane work
```

Commands it performs internally:

```text
CreateVolume()
DeleteVolume()
ControllerPublishVolume()   → attach
ControllerUnpublishVolume() → detach
ExpandVolume()
```

---

## B. Node Plugin

Runs as a **DaemonSet** (one pod on each worker node).

Responsible for:

* Formatting disk (`ext4`, `xfs`)
* Mounting disk on node
* Mounting into container
* Unmounting

Think:

```text
Node-level work
```

---

✅ Amazon Elastic Kubernetes Service (EKS)


### What it does:

* Connects to Kubernetes API server
* Fetches all worker nodes

Example output:

```text

ip-10-0-2-11 Ready
```

Meaning:

Cluster is reachable.

---

## Step 2: Check if driver already installed

Command:

```bash
kubectl get pods -n kube-system | grep ebs
```

### What this does:

### `kubectl get pods`

Lists pods.

### `-n kube-system`

Looks in **kube-system namespace**.

Why?

System components live there.

### `|`

Pipe output to next command.

### `grep ebs`

Filters only lines containing "ebs".

Output:

```text
ebs-csi-controller-xxxxx
ebs-csi-node-yyyyy
```

If nothing appears → not installed.

---

## Step 3: Create IAM role for service account (IRSA)

Very important.

EBS CSI needs AWS permissions.

Required permissions:

* `ec2:CreateVolume`
* `ec2:DeleteVolume`
* `ec2:AttachVolume`
* `ec2:DetachVolume`

### Create IAM policy

Official AWS managed policy:

[AmazonEBSCSIDriverPolicy](https://docs.aws.amazon.com/eks/latest/userguide/ebs-csi.html?utm_source=chatgpt.com)

---

## Step 4: Associate IAM role using **eksctl**

[eksctl official site](https://eksctl.io/?utm_source=chatgpt.com)

Command:

```bash
eksctl create iamserviceaccount \
  --name ebs-csi-controller-sa \
  --namespace kube-system \
  --cluster my-cluster \
  --role-name AmazonEKS_EBS_CSI_DriverRole \
  --attach-policy-arn arn:aws:iam::aws:policy/service-role/AmazonEBSCSIDriverPolicy \
  --approve
```

---

### What each flag means

## `eksctl create iamserviceaccount`

Creates:

* Kubernetes service account
* AWS IAM role
* Links both together

---

## `--name ebs-csi-controller-sa`

Service account name.

Driver pods will use this identity.

---

## `--namespace kube-system`

Create it in:

```text
kube-system
```

---

## `--cluster my-cluster`

Which EKS cluster to use.

---

## `--role-name AmazonEKS_EBS_CSI_DriverRole`

IAM role name.

Created in AWS IAM.

---

## `--attach-policy-arn`

Attach AWS permission policy.

Without this:

❌ Driver cannot create volumes.

---

## `--approve`

Actually execute.

Without it:

Dry run only.

---

## Step 5: Install EBS CSI Add-on

Command:

```bash
aws eks create-addon \
  --cluster-name my-cluster \
  --addon-name aws-ebs-csi-driver
```

### What this does:

### `aws eks`

### `create-addon`

### `--cluster-name`

### `--addon-name aws-ebs-csi-driver`

# 5. Create StorageClass Using EBS CSI Driver

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: ebs-sc
provisioner: ebs.csi.aws.com
parameters:
  type: gp3
  fsType: ext4
allowVolumeExpansion: true
reclaimPolicy: Delete
volumeBindingMode: WaitForFirstConsumer
```

---

## Field explanations

### `provisioner: ebs.csi.aws.com`

Use EBS CSI driver.

This is how Kubernetes knows **which driver to call**.

---

### `type: gp3`

AWS EBS volume type.

Options:

* `gp2`
* `gp3`
* `io1`
* `io2`

Recommended:

✅ `gp3`

---

### `fsType: ext4`

Filesystem format.

Driver formats disk before mounting.

---

### `allowVolumeExpansion: true`

Lets you increase PVC size later.

---

### `reclaimPolicy: Delete`

Delete EBS disk when PVC deleted.

For databases, sometimes use:

```yaml
Retain
```

---

### `volumeBindingMode: WaitForFirstConsumer`

Very important.

Prevents wrong Availability Zone issue.

# 6. Test Dynamic Provisioning

Create PVC:

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: test-pvc
spec:
  accessModes:
  - ReadWriteOnce
  storageClassName: ebs-sc
  resources:
    requests:
      storage: 5Gi
```

Apply:

```bash
kubectl apply -f pvc.yaml
```

### What it does

Creates PVC object.

This triggers:

```text
PVC → StorageClass → EBS CSI Driver → AWS EBS Volume → PV
```

---

Check:

```bash
kubectl get pvc
```

Output:

```text
test-pvc   Bound
```

---

Check PV:

```bash
kubectl get pv
```

---

Check actual AWS volume:

```bash
aws ec2 describe-volumes
```

### What it does

AWS CLI lists all EBS volumes.

You should see newly created volume.

# 7. Common Troubleshooting

## PVC stuck in Pending

Check:

```bash
kubectl describe pvc test-pvc
```

Shows events.

Common reasons:

* CSI driver missing
* StorageClass typo
* IAM permissions missing

---

## AccessDenied errors

Check controller logs:

```bash
kubectl logs -n kube-system deployment/ebs-csi-controller
```

Usually IAM issue.

---

## Driver pods not running

Check:

```bash
kubectl get pods -n kube-system
```

# Interview One-Liner

**The AWS EBS CSI Driver is a Kubernetes storage plugin that enables dynamic provisioning by allowing Kubernetes to create, attach, mount, resize, and delete Amazon EBS volumes automatically through StorageClasses and PersistentVolumeClaims.**

---

## Real interview follow-up they may ask:

**“What is the difference between ebs-csi-controller and ebs-csi-node?”**

Answer:

* **ebs-csi-controller** → handles AWS API operations like create/attach/delete volume
* **ebs-csi-node** → runs on each node and handles mount/unmount inside the node

That’s a very common DevOps interview question.
