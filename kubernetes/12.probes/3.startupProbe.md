# Startup Probe in Kubernetes (Detailed)

## Why do we need `startupProbe`?

Some applications take **long time to start**, for example:

* **Spring Boot** app loading dependencies
* Cache warm-up
* DB migration
* JVM startup
* Large configuration loading

Problem without `startupProbe`:

```text
Container starts
   ↓
Liveness probe starts immediately
   ↓
App not ready yet
   ↓
Liveness fails
   ↓
Container restarted
   ↓
CrashLoopBackOff
```

Kubernetes thinks:

> “App is unhealthy”

But actually:

> “App is just still starting”

That’s why `startupProbe` exists.

---

# What does `startupProbe` do?

It tells **kubelet**:

> **"Don't run readiness or liveness probes until my app has started successfully."**

---

## Lifecycle flow

```text
Container starts
   ↓
Startup probe begins
   ↓
If startup probe FAILS → keep retrying
   ↓
If failures exceed limit → restart container
   ↓
If startup probe SUCCEEDS
   ↓
Startup probe stops forever
   ↓
Readiness probe starts
   ↓
Liveness probe starts
```

---

# Important behavior

### While `startupProbe` is running:

```text
Readiness probe = Disabled
Liveness probe = Disabled
```

Only startup probe runs.

---

### After `startupProbe` succeeds:

```text
Startup probe = Disabled forever
Readiness probe = Enabled
Liveness probe = Enabled
```

It runs only during startup.

# Full YAML Example

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: startup-probe-demo
spec:
  containers:
  - name: app
    image: myapp:latest

    startupProbe:
      httpGet:                        # Probe type
        path: /health                # Required: endpoint to check
        port: 8080                   # Required: container port
        host: 127.0.0.1              # Optional, default: Pod IP
        scheme: HTTP                 # Default: HTTP
        httpHeaders:                 # Optional
        - name: Custom-Header
          value: my-value

      initialDelaySeconds: 0         # Default: 0 sec
      periodSeconds: 10              # Default: 10 sec
      timeoutSeconds: 1              # Default: 1 sec
      successThreshold: 1            # Default: 1 (must stay 1 for startupProbe)
      failureThreshold: 3            # Default: 3
      terminationGracePeriodSeconds: 30   # Default: inherit Pod value
```

---

# Explain each field

---

## 1. `httpGet`

Probe type.

Kubelet sends HTTP request:

```text
GET http://<pod-ip>:8080/health
```

If response is:

```text
200–399 → Success
Other / timeout → Failure
```

---

## 2. `path`

```yaml
path: /health
```

Endpoint to check.

Examples:

```yaml
/health
/actuator/health
/ready
```

### Default:

❌ No default → **must specify**

---

## 3. `port`

```yaml
port: 8080
```

Container port to probe.

### Default:

❌ No default → **must specify**

---

## 4. `host`

```yaml
host: 127.0.0.1
```

Where kubelet connects.

### Default:

```text
Pod IP
```

Usually omitted.

---

## 5. `scheme`

```yaml
scheme: HTTP
```

Protocol.

Options:

* `HTTP`
* `HTTPS`

### Default:

```text
HTTP
```

---

## 6. `httpHeaders`

```yaml
httpHeaders:
- name: Host
  value: myapp.internal
```

Custom request headers.

Optional.

### Default:

```text
None
```

---

## 7. `initialDelaySeconds`

```yaml
initialDelaySeconds: 20
```

Wait this long **after container starts** before first probe.

### Default:

```text
0 sec
```

### Function:

```text
Container starts
Wait 20 sec
First startup probe runs
```

Usually not needed.

---

## 8. `periodSeconds`

```yaml
periodSeconds: 10
```

Run probe every 10 sec.

### Default:

```text
10 sec
```

---

## 9. `timeoutSeconds`

```yaml
timeoutSeconds: 2
```

How long kubelet waits for probe response.

### Default:

```text
1 sec
```

If app doesn't respond within timeout → failure.

---

## 10. `successThreshold`

```yaml
successThreshold: 1
```

How many successes needed.

### Default:

```text
1
```

For startup probe, must remain **1**.

Why?

Once app starts successfully, startup phase is over.

---

## 11. `failureThreshold`

```yaml
failureThreshold: 30
```

How many failed probes allowed before restart.

### Default:

```text
3
```

Important formula:

```text
Allowed startup time =
failureThreshold × periodSeconds
```

Example:

```text
30 × 10 = 300 sec
```

App gets **5 minutes** to start.

---

## 12. `terminationGracePeriodSeconds`

```yaml
terminationGracePeriodSeconds: 30
```

Time given to container to shut down gracefully before force kill.

### Default:

```text
Uses Pod-level terminationGracePeriodSeconds
(default Pod value = 30 sec)
```

---

# Example timeline

Configuration:

```yaml
periodSeconds: 10
failureThreshold: 6
```

Timeline:

```text
10:00:00 Container starts
10:00:00 Probe 1 fail
10:00:10 Probe 2 fail
10:00:20 Probe 3 fail
10:00:30 Probe 4 fail
10:00:40 Probe 5 fail
10:00:50 Probe 6 fail
10:00:50 Container restarted
```

Allowed startup time:

```text
6 × 10 = 60 sec
```

# Probe types possible

## HTTP probe

```yaml
startupProbe:
  httpGet:
    path: /health
    port: 8080
```

---

## TCP probe

Checks if port opens.

```yaml
startupProbe:
  tcpSocket:
    port: 8080
```

---

## Exec probe

Runs command inside container.

```yaml
startupProbe:
  exec:
    command:
    - cat
    - /tmp/healthy
```

---

# Best practice

For slow apps:

```yaml
startupProbe:
  httpGet:
    path: /actuator/health
    port: 8080
  periodSeconds: 10
  failureThreshold: 30
```

This gives:

```text
30 × 10 = 300 sec startup allowance
```

Simple and reliable.

---

# Interview one-liner

**Startup probe is used for slow-starting applications; it temporarily disables readiness and liveness checks until the application starts successfully, preventing unnecessary restarts during startup.**
