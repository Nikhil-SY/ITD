# Readiness Probe in Kubernetes (Detailed)

## Why do we need `readinessProbe`?

Sometimes application **is running**, but **cannot serve traffic yet** or **temporarily cannot serve traffic**.

Examples:

* App still loading
* Waiting for **MySQL** / **PostgreSQL** connection
* Cache not warmed up
* Temporary overload
* Dependency service down

Problem without `readinessProbe`:

```text
Container starts
      ↓
Pod marked Ready immediately
      ↓
Service sends traffic
      ↓
App not ready
      ↓
Users get errors
```

Kubernetes thinks:

> **Container running = app ready**

But that may not be true.

That’s why **`readinessProbe`** exists.

---

# What does `readinessProbe` do?

It tells **kubelet**:

> **"Check if my app can receive traffic. If not, stop sending traffic—but don’t restart me."**

---

# Lifecycle flow

```text
Container starts
    ↓
(Optional startupProbe runs first)
    ↓
Readiness probe starts
    ↓
If readiness succeeds
    ↓
Pod marked Ready
    ↓
Service sends traffic
```

If later readiness fails:

```text
Readiness probe fails
    ↓
Container NOT restarted
    ↓
Pod marked NotReady
    ↓
Endpoint Controller removes pod from Service
    ↓
No new traffic goes to pod
```

---

# Important behavior

### On readiness failure:

```text
Container keeps running
Pod stays same
Pod IP stays same
Traffic stops
```

**Readiness never restarts container.**

# Full YAML Example (`httpGet`)

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: readiness-probe-demo
spec:
  containers:
  - name: app
    image: myapp:latest

    readinessProbe:
      httpGet:                          # Probe type
        path: /ready                    # Required
        port: 8080                      # Required
        host: 127.0.0.1                 # Optional, default: Pod IP
        scheme: HTTP                    # Default: HTTP
        httpHeaders:                    # Optional
        - name: Custom-Header
          value: my-value

      initialDelaySeconds: 0            # Default: 0 sec
      periodSeconds: 10                 # Default: 10 sec
      timeoutSeconds: 1                 # Default: 1 sec
      successThreshold: 1               # Default: 1 (can be >1 for readiness)
      failureThreshold: 3               # Default: 3
      terminationGracePeriodSeconds: 30 # Default: Pod value (usually 30)
```

---

# Explain each field

## 1. `httpGet`

Probe type.

Kubelet sends:

```text
GET http://<pod-ip>:8080/ready
```

Success if:

```text
HTTP 200–399
```

Failure if:

* Timeout
* Connection refused
* HTTP 500

---

## 2. `path`

```yaml
path: /ready
```

Endpoint to check.

Examples:

```yaml
/ready
/actuator/health/readiness
/health
```

### Default

❌ No default → **must specify**

---

## 3. `port`

```yaml
port: 8080
```

Container port to probe.

### Default

❌ No default → **must specify**

---

## 4. `host`

```yaml
host: 127.0.0.1
```

Where kubelet connects.

### Default

```text
Pod IP
```

Usually omitted.

---

## 5. `scheme`

```yaml
scheme: HTTP
```

Options:

* `HTTP`
* `HTTPS`

### Default

```text
HTTP
```

---

## 6. `httpHeaders`

```yaml
httpHeaders:
- name: Host
  value: myapp.internal
```

Optional custom headers.

### Default

```text
None
```

---

## 7. `initialDelaySeconds`

```yaml
initialDelaySeconds: 20
```

Wait after **container starts** before first readiness check.

### Default

```text
0 sec
```

Useful if app needs warm-up time.

---

## 8. `periodSeconds`

```yaml
periodSeconds: 10
```

Run readiness check every 10 sec.

### Default

```text
10 sec
```

---

## 9. `timeoutSeconds`

```yaml
timeoutSeconds: 1
```

How long kubelet waits.

### Default

```text
1 sec
```

---

## 10. `successThreshold`

```yaml
successThreshold: 2
```

How many consecutive successes needed to mark pod **Ready again**.

### Default

```text
1
```

**Important:** Unlike liveness/startup, readiness **can be > 1**.

Example:

```text
Probe failed → Pod removed from Service
Need 2 successful probes before adding it back
```

This avoids traffic flapping.

---

## 11. `failureThreshold`

```yaml
failureThreshold: 3
```

How many failures before pod becomes **NotReady**.

### Default

```text
3
```

Example:

```text
3 failures × 10 sec = ~30 sec
```

Then pod removed from Service.

---

## 12. `terminationGracePeriodSeconds`

```yaml
terminationGracePeriodSeconds: 30
```

### Important:

This field **does not apply to readinessProbe**, because readiness **does not kill or restart** the container.

So even though Kubernetes accepts the field in probe config, it has **no effect for readiness**.

---

# `exec` readiness probe

Instead of HTTP, kubelet can run a command.

## Example

```yaml
readinessProbe:
  exec:
    command:
    - cat
    - /tmp/ready
```

Kubelet runs:

```bash
cat /tmp/ready
```

### Success

```text
Exit code 0 → Pod Ready
```

### Failure

```text
Non-zero exit code → Pod NotReady
```

---

# `tcpSocket` readiness probe

Checks if port is accepting connections.

```yaml
readinessProbe:
  tcpSocket:
    port: 8080
```

If TCP connection opens → Ready.

# Example timeline

Config:

```yaml
periodSeconds: 10
failureThreshold: 3
```

Timeline:

```text
10:00:00 Pod Ready
10:05:00 App loses DB connection
10:05:00 Probe fail 1
10:05:10 Probe fail 2
10:05:20 Probe fail 3
10:05:20 Pod removed from Service
```

Container still running.

# Startup vs Readiness vs Liveness

| Probe              | Purpose                  | Failure action          |
| ------------------ | ------------------------ | ----------------------- |
| **startupProbe**   | Has app started?         | Restart container       |
| **readinessProbe** | Can app receive traffic? | Remove pod from Service |
| **livenessProbe**  | Is app still healthy?    | Restart container       |

---

# Best practice

Typical setup:

```yaml
readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  periodSeconds: 10
  failureThreshold: 3
  successThreshold: 2
```

---

# Interview one-liner

**Readiness probe checks whether the application can serve traffic; if it fails, Kubernetes removes the pod from Service endpoints without restarting the container, and adds it back when readiness succeeds again.**
