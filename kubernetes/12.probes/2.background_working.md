Perfect question.

Here’s **which Kubernetes component/resource is responsible at each step**:

```text
Container readiness probe fails
        ↓
Kubelet marks container NotReady
        ↓
Pod Ready condition becomes False
        ↓
Endpoint Controller updates Service endpoints
        ↓
Pod removed from Service
        ↓
No new traffic goes to that Pod
```

## 1. Container readiness probe fails

### Responsible: **kubelet**

* **Kubelet** runs on every worker node.
* It executes the **readiness probe** (`HTTP`, `TCP`, or `exec`) inside/against the container.
* If probe fails → kubelet detects it.

```text
Node
 └── kubelet checks /ready endpoint
```

---

## 2. Kubelet marks container "Not Ready"

### Responsible: **kubelet**

Kubelet updates **container status** in Pod status:

```yaml
containerStatuses:
- name: app
  ready: false
```

So still **kubelet**.

---

## 3. Pod Ready condition becomes False

### Responsible: **kubelet**

Kubelet evaluates:

```text
All containers ready? → Pod Ready=True
Any container not ready? → Pod Ready=False
```

It updates Pod condition:

```yaml
conditions:
- type: Ready
  status: "False"
```

Stored in **etcd** through **kube-apiserver**.

---

## 4. Endpoint Controller updates Service endpoints

### Responsible: **Endpoint Controller inside kube-controller-manager**

This controller watches:

* Pods
* Services
* Pod readiness changes

It sees:

```text
Pod Ready=False
```

Then updates **EndpointSlice / Endpoints** objects:

```bash
kubectl get endpoints
kubectl get endpointslices
```

Removes Pod IP.

---

## 5. Pod removed from Service

### Responsible: **kube-proxy**

After EndpointSlice changes:

* **kube-proxy** on every node notices updated endpoints
* Updates **iptables/IPVS rules**

Example:

```text
Old:
Service → Pod1, Pod2, Pod3

New:
Service → Pod1, Pod3
```

Pod2 removed.

---

## 6. No new traffic goes to Pod

### Responsible: **Service + kube-proxy**

* **Kubernetes Service** decides logical routing
* **kube-proxy** enforces actual routing rules

Traffic now avoids that Pod.

---

# Full ownership map

| Step                      | Responsible component                             |
| ------------------------- | ------------------------------------------------- |
| Run readiness probe       | **kubelet**                                       |
| Mark container NotReady   | **kubelet**                                       |
| Update Pod Ready=False    | **kubelet**                                       |
| Store updated Pod status  | **kube-apiserver + etcd**                         |
| Detect readiness change   | **Endpoint Controller (kube-controller-manager)** |
| Update Service endpoints  | **Endpoint Controller**                           |
| Update node routing rules | **kube-proxy**                                    |
| Stop sending traffic      | **Service + kube-proxy**                          |

---

## Easy way to remember

```text
kubelet → detects failure
API server → stores status
Endpoint Controller → removes endpoint
kube-proxy → stops routing traffic
```

## Interview one-liner

**Kubelet runs the readiness probe and marks the pod NotReady, the API server stores the updated status, the Endpoint Controller removes the pod from Service endpoints, and kube-proxy updates routing rules so traffic no longer reaches that pod.**
