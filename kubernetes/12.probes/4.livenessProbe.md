# Liveness Probe in Kubernetes (Detailed)

## Why do we need `livenessProbe`?

Sometimes application **starts successfully**, but later becomes **unhealthy**:

Examples:

* Application **hangs / deadlocks**
* Thread stuck
* Memory issue
* App stops responding
* Infinite loop
* Health endpoint stops working

Problem without `livenessProbe`:

```text
Container process is still running
       ↓
Kubernetes thinks app is healthy
       ↓
But app is not responding
       ↓
Traffic keeps failing
```

Kubernetes only sees:

> **Process alive = container running**

But actual app may be broken.

That’s why **`livenessProbe`** exists.

---

# What does `livenessProbe` do?

It tells **kubelet**:

> **"Check whether my app is still alive. If not, restart the container."**

---

# Lifecycle flow

```text
Container starts
    ↓
(Optional startupProbe runs first)
    ↓
Liveness probe starts
    ↓
If liveness succeeds → do nothing
    ↓
If liveness fails repeatedly
    ↓
Kubelet kills container
    ↓
Container restarts
```

---

# Important behavior

### On liveness failure:

```text
Container restarted
Pod stays same
Pod IP stays same
```

**It restarts container, not pod.**

---

# Full YAML Example

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: liveness-probe-demo
spec:
  containers:
  - name: app
    image: myapp:latest

    livenessProbe:
      httpGet:                          # Probe type
        path: /health                   # Required
        port: 8080                      # Required
        host: 127.0.0.1                 # Optional, default: Pod IP
        scheme: HTTP                    # Default: HTTP
        httpHeaders:                    # Optional
        - name: Custom-Header
          value: my-value

      initialDelaySeconds: 0            # Default: 0 sec
      periodSeconds: 10                 # Default: 10 sec
      timeoutSeconds: 1                 # Default: 1 sec
      successThreshold: 1               # Default: 1 (must be 1)
      failureThreshold: 3               # Default: 3
      terminationGracePeriodSeconds: 30 # Default: Pod value (usually 30)
```

---

# Explain each field

---

## 1. `httpGet`

Probe type.

Kubelet sends:

```text
GET http://<pod-ip>:8080/health
```

Success if:

```text
HTTP 200–399
```

Failure if:

* Timeout
* Connection refused
* 500 error

---

## 2. `path`

```yaml
path: /health
```

Endpoint to check.

Examples:

```yaml
/health
/actuator/health
/live
```

### Default:

❌ No default → **must specify**

---

## 3. `port`

```yaml
port: 8080
```

Container port to probe.

### Default:

❌ No default → **must specify**

---

## 4. `host`

```yaml
host: 127.0.0.1
```

Where kubelet connects.

### Default:

```text
Pod IP
```

Usually omitted.

---

## 5. `scheme`

```yaml
scheme: HTTP
```

Protocol.

Options:

* `HTTP`
* `HTTPS`

### Default:

```text
HTTP
```

---

## 6. `httpHeaders`

```yaml
httpHeaders:
- name: Host
  value: myapp.internal
```

Custom request headers.

### Default:

```text
None
```

---

## 7. `initialDelaySeconds`

```yaml
initialDelaySeconds: 30
```

Wait after **container starts** before first liveness check.

### Default:

```text
0 sec
```

### Why useful?

Prevents liveness from killing app too early during startup.

---

## 8. `periodSeconds`

```yaml
periodSeconds: 10
```

Run probe every 10 sec.

### Default:

```text
10 sec
```

---

## 9. `timeoutSeconds`

```yaml
timeoutSeconds: 2
```

How long kubelet waits for response.

### Default:

```text
1 sec
```

If no response in time → failure.

---

## 10. `successThreshold`

```yaml
successThreshold: 1
```

Number of successful probes needed.

### Default:

```text
1
```

For **liveness**, must be **1**.

Reason:

Once app responds, it's alive again.

---

## 11. `failureThreshold`

```yaml
failureThreshold: 3
```

Number of consecutive failures before restart.

### Default:

```text
3
```

Formula:

```text
Restart after ≈ failureThreshold × periodSeconds
```

Example:

```text
3 × 10 = 30 sec
```

After ~30 sec of failures → restart.

---

## 12. `terminationGracePeriodSeconds`

```yaml
terminationGracePeriodSeconds: 30
```

Grace time before force killing container.

### Default:

```text
Uses Pod value (default 30 sec)
```

---

Config:

# Probe types possible

## HTTP probe

```yaml
livenessProbe:
  httpGet:
    path: /health
    port: 8080
```

---

## TCP probe

Checks whether port is accepting connections.

```yaml
livenessProbe:
  tcpSocket:
    port: 8080
```

---

## Exec probe

Runs command inside container.

```yaml
livenessProbe:
  exec:
    command:
    - cat
    - /tmp/healthy
```

---

# Startup vs Readiness vs Liveness

| Probe              | Purpose                  | Failure action          |
| ------------------ | ------------------------ | ----------------------- |
| **startupProbe**   | Has app started?         | Restart container       |
| **readinessProbe** | Can app receive traffic? | Remove pod from Service |
| **livenessProbe**  | Is app still alive?      | Restart container       |

---

# Best practice

Typical production setup:

```yaml
livenessProbe:
  httpGet:
    path: /live
    port: 8080
  periodSeconds: 10
  failureThreshold: 3
```

For **`livenessProbe`**, `exec` is another probe type where **kubelet** runs a command **inside the container**.

# `livenessProbe` with `exec`

## Example YAML

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: liveness-exec-demo
spec:
  containers:
  - name: app
    image: nginx:latest

    livenessProbe:
      exec:                               # Probe type: run command inside container
        command:                          # Required
        - cat
        - /tmp/healthy

      initialDelaySeconds: 0             # Default: 0 sec
      periodSeconds: 10                  # Default: 10 sec
      timeoutSeconds: 1                  # Default: 1 sec
      successThreshold: 1                # Default: 1 (must be 1 for liveness)
      failureThreshold: 3                # Default: 3
      terminationGracePeriodSeconds: 30  # Default: Pod value (usually 30)
```

---

# How `exec` works

Kubelet runs:

```bash
cat /tmp/healthy
```

inside the container.

### Success condition

If command exits with:

```text
Exit code = 0
```

Probe **passes**.

### Failure condition

If command exits with:

```text
Non-zero exit code (1, 2, etc.)
```

Probe **fails**.

---

# Example scenarios

### Healthy app

File exists:

```text
/tmp/healthy
```

Command:

```bash
cat /tmp/healthy
```

Result:

```text
Exit code 0 → probe success
```

---

### Unhealthy app

File deleted:

```bash
rm /tmp/healthy
```

Next probe:

```bash
cat /tmp/healthy
```

Result:

```text
cat: No such file
Exit code 1 → probe failure
```

After `failureThreshold` failures → container restarts.

---

# `exec.command` field

```yaml
exec:
  command:
  - cat
  - /tmp/healthy
```

### Meaning

Kubernetes passes this directly to the container runtime.

Equivalent to:

```bash
cat /tmp/healthy
```

### Default

❌ **No default** — required for `exec`

---

# Common `exec` examples

### Check if file exists

```yaml
exec:
  command:
  - test
  - -f
  - /tmp/healthy
```

---

### Check process running

```yaml
exec:
  command:
  - pgrep
  - java
```

---

### Custom health script

```yaml
exec:
  command:
  - /bin/sh
  - -c
  - /app/health-check.sh
```

---

# When to use `exec`

Use `exec` when:

* No HTTP health endpoint available
* Need to check files/processes inside container
* Need custom logic

Prefer `httpGet` when possible (simpler and usually cheaper).

---

## Interview one-liner

**With an `exec` liveness probe, kubelet runs a command inside the container; if the command exits non-zero repeatedly, Kubernetes restarts the container.**
