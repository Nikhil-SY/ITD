## Helm template functions inside `{{ ... }}` (placeholders)

Inside Helm placeholders, you can use **functions** to modify values, format YAML, validate inputs, or apply logic.

General syntax:

```yaml
{{ FUNCTION ARGUMENTS }}
```

or with **pipeline** (most common):

```yaml
{{ VALUE | FUNCTION }}
```

Think of `|` as: **“take this value, then apply this function.”**

---

# 1. Default function → `default`

Use when a value may be missing.

### Syntax

```yaml
{{ .Values.name | default "guest" }}
```

### Example

**values.yaml**

```yaml
# name not provided
```

**template**

```yaml
user: {{ .Values.name | default "guest" }}
```

**Output**

```yaml
user: guest
```

**Use case:** fallback value

---

# 2. Required function → `required`

Make a value mandatory.

### Syntax

```yaml
{{ required "name is required" .Values.name }}
```

### Example

```yaml
image: nginx:{{ required "tag required" .Values.tag }}
```

If missing:

```text
Error: tag required
```

**Use case:** stop deployment if important value missing

---

# 3. Quote function → `quote`

Wrap value in quotes.

### Example

```yaml
env: {{ .Values.environment | quote }}
```

If:

```yaml
environment: prod
```

Output:

```yaml
env: "prod"
```

**Use case:** safer YAML strings

---

# 4. Upper / Lower / Title

Change text case.

```yaml
{{ "hello" | upper }}
```

Output:

```text
HELLO
```

```yaml
{{ "HELLO" | lower }}
```

Output:

```text
hello
```

```yaml
{{ "hello world" | title }}
```

Output:

```text
Hello World
```

---

# 5. Replace

Replace text.

```yaml
{{ "my-app" | replace "-" "_" }}
```

Output:

```text
my_app
```

---

# 6. Trim

Remove spaces.

```yaml
{{ " hello " | trim }}
```

Output:

```text
hello
```

---

# 7. Indent

Add spaces to **each line**.

```yaml
summary: {{ "hello\nworld" | indent 2 }}
```

Output:

```yaml
summary:   hello
  world
```

---

# 8. Nindent

**Newline + indent**

```yaml
summary:{{ "hello\nworld" | nindent 2 }}
```

Output:

```yaml
summary:
  hello
  world
```

Most common for YAML blocks.

---

# 9. ToYaml

Convert object/list to YAML.

### values.yaml

```yaml
labels:
  app: nginx
  env: prod
```

### template

```yaml
metadata:
  labels:{{ .Values.labels | toYaml | nindent 4 }}
```

### Output

```yaml
metadata:
  labels:
    app: nginx
    env: prod
```

Very important in Helm.

---

# 10. ToJson

Convert to JSON.

```yaml
{{ .Values.labels | toJson }}
```

Output:

```json
{"app":"nginx","env":"prod"}
```

---

# 11. Len

Get length.

```yaml
{{ len .Values.items }}
```

If list has 3 items:

```text
3
```

---

# 12. Join

Join list into string.

### values.yaml

```yaml
items:
  - apple
  - mango
```

### template

```yaml
{{ .Values.items | join "," }}
```

Output:

```text
apple,mango
```

---

# 13. Split

Split string into list.

```yaml
{{ "a,b,c" | split "," }}
```

---

# 14. printf

Format strings.

```yaml
{{ printf "%s-%s" "app" "prod" }}
```

Output:

```text
app-prod
```

---

# 15. Include

Call another template.

```yaml
{{ include "mychart.fullname" . }}
```

Used for reusable template snippets.

# 16. tpl

Render a string as template.

If value contains template syntax itself.

Advanced usage.

## `if` and `enabled` in Helm placeholders

In Helm, `if` is used for **conditional rendering**—render something **only if a condition is true**.

`enabled` is just a **common boolean field name** in `values.yaml` (not a special Helm keyword).

Together they’re often used like this:

```yaml
{{- if .Values.service.enabled }}
# create Service resource
{{- end }}
```

Meaning: **Only create this resource if `service.enabled` is `true`.**

---

# 1. `if` syntax

```yaml
{{ if CONDITION }}
  content
{{ end }}
```

Or commonly with whitespace trimming:

```yaml
{{- if CONDITION }}
  content
{{- end }}
```

`{{-` removes extra spaces/newlines.

---

# 2. Example with `enabled`

### `values.yaml`

```yaml
service:
  enabled: true
```

### Template

```yaml
{{- if .Values.service.enabled }}
apiVersion: v1
kind: Service
metadata:
  name: myservice
{{- end }}
```

### Output (when `enabled: true`)

```yaml
apiVersion: v1
kind: Service
metadata:
  name: myservice
```

---

### If `enabled: false`

**values.yaml**

```yaml
service:
  enabled: false
```

### Output

```text
(nothing rendered)
```

The whole block is skipped.

---

# 3. Why use `enabled`?

To let users **turn resources on/off**.

Example:

```yaml
ingress:
  enabled: false
autoscaling:
  enabled: true
serviceAccount:
  enabled: false
```

Template checks:

```yaml
{{- if .Values.ingress.enabled }}
... ingress YAML ...
{{- end }}
```

Very common in charts.

---

# 4. How `if` decides true/false

These are **false**:

```yaml
false
null
""
0
[]
{}
```

Everything else is usually **true**.

Example:

```yaml
{{ if .Values.name }}
```

If name is empty → block skipped.

---

# 5. `if / else`

```yaml
{{- if .Values.service.enabled }}
service enabled
{{- else }}
service disabled
{{- end }}
```

If `enabled: false`:

```text
service disabled
```

---

# 6. `if not`

Check opposite condition:

```yaml
{{- if not .Values.service.enabled }}
service is disabled
{{- end }}
```

# Interview-style summary

## What is `if` in Helm?

Conditional statement to render YAML only when condition is true.

### Syntax

```yaml
{{- if CONDITION }}
...
{{- end }}
```

---

## What is `enabled`?

A **user-defined boolean value** in `values.yaml`.

Example:

```yaml
service:
  enabled: true
```

---

## Common usage

```yaml
{{- if .Values.service.enabled }}
apiVersion: v1
kind: Service
{{- end }}
```

### If `enabled: true`

→ Resource created

### If `enabled: false`

→ Resource skipped

---

### Why important?

Used to make Helm charts **configurable** (turn features/resources on or off).
