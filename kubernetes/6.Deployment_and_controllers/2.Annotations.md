# 🚀 `kubectl.kubernetes.io/default-container` Annotation

---

# 1. What is this?

## Definition

This annotation tells Kubernetes:

```text
"Which container should be treated as default when -c is NOT specified"
```

---

# 2. Why do we need this?

---

## Problem in Multi-Container Pod

```bash
kubectl exec -it my-pod -- /bin/bash
```

👉 By default:

```text
First container is selected ❌
```

---

## Solution

👉 Set default container using annotation

---

# 3. Where to Use This?

👉 Inside **Pod template metadata**

---

## 🔹 In Deployment (Most Common)

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  template:
    metadata:
      annotations:
        kubectl.kubernetes.io/default-container: app
    spec:
      containers:
      - name: app
        image: my-app
      - name: sidecar
        image: busybox
```

---

## 🔹 In Pod (Direct)

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-pod
  annotations:
    kubectl.kubernetes.io/default-container: app
spec:
  containers:
  - name: app
    image: nginx
  - name: sidecar
    image: busybox
```

---

# 4. How It Works

---

## Without annotation

```bash
kubectl exec -it my-pod -- /bin/bash
```

👉 Goes to:

```text
First container
```

---

## With annotation

```yaml
kubectl.kubernetes.io/default-container: app
```

---

Now:

```bash
kubectl exec -it my-pod -- /bin/bash
```

👉 Goes to:

```text
app container ✅
```

---

# 5. Where It Applies

---

This annotation affects:

| Command          | Behavior                 |
| ---------------- | ------------------------ |
| `kubectl exec`   | ✔ Uses default container |
| `kubectl logs`   | ✔ Uses default container |
| `kubectl attach` | ✔ Uses default container |

---

# 6. Real-World Use Case

---

## Multi-container Pod

```yaml
containers:
- name: app
- name: sidecar
```

---

### Problem

Developers run:

```bash
kubectl logs my-pod
```

👉 Logs from:

```text
sidecar (wrong container) ❌
```

---

### Solution

```yaml
annotations:
  kubectl.kubernetes.io/default-container: app
```

---

👉 Now:

```bash
kubectl logs my-pod
```

👉 Logs from:

```text
app container ✅
```

---

# 7. Important Notes

---

## 🔹 Not mandatory

* Optional feature

---

## 🔹 Only affects kubectl

* Does NOT affect Kubernetes runtime
* Only CLI behavior

---

## 🔹 Must match container name

```yaml
containers:
- name: app
```

👉 Annotation must be:

```yaml
app ✅
```

---

# 8. Common Mistakes

---

❌ Putting annotation at wrong level

Wrong:

```yaml
metadata:
  annotations:   ❌ (top-level in Deployment)
```

Correct:

```yaml
spec:
  template:
    metadata:
      annotations:   ✅
```

---

❌ Wrong container name

```yaml
default-container: myapp  ❌ (doesn’t exist)
```
