# 🚀 DaemonSet in Kubernetes (Complete Guide)

---

# 1. What is a DaemonSet?

## Definition

A **DaemonSet** ensures that **one Pod runs on every node** (or selected nodes) in the cluster.

---

## Key Idea

```text
1 Node = 1 Pod
```

👉 Automatically:

* New node added → Pod created
* Node removed → Pod deleted

---

# 2. Why DaemonSet?

Used for **node-level services**

---

## Common Use Cases

✔ Log collection (Fluentd)
✔ Monitoring (Prometheus Node Exporter)
✔ Networking (CNI plugins)
✔ Security agents

---

# 3. Architecture

```text
DaemonSet
   ↓
One Pod per Node
   ↓
Node1   Node2   Node3
  ✔       ✔       ✔
```

---

# 4. Basic DaemonSet YAML

```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: nginx-daemon
spec:
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
```

---


---

## 🔹 metadata

```yaml

  name: nginx-daemon
```

---

## 🔹 spec

---

### 🔸 selector (IMPORTANT)

```yaml
selector:
  matchLabels:
    app: nginx
```

👉 Identifies Pods managed by DaemonSet

---

### 🔸 template (Pod Template)

```yaml
template:
```

Defines Pod configuration

---

### 🔸 template.metadata.labels

```yaml
labels:
  app: nginx
```

👉 Must match selector

---

### 🔸 template.spec.containers

```yaml
containers:
- name: nginx
  image: nginx:1.25
```

---

# 🔥 IMPORTANT RULE

```text
selector.matchLabels == template.metadata.labels
```

# 6. Key Difference from Deployment

| Feature       | Deployment   | DaemonSet          |
| ------------- | ------------ | ------------------ |
| Pods per node | Multiple     | One                |
| Scaling       | Manual       | Automatic per node |
| Use case      | Applications | Node services      |

# 9. Node Selection (IMPORTANT)

---

## 🔹 Run on specific nodes using labels

### Step 1: Label node

```bash
kubectl label node node1 env=prod
```

---

### Step 2: Use nodeSelector

```yaml
spec:
  template:
    spec:
      nodeSelector:
        env: prod
```

👉 Runs only on nodes with `env=prod`

---

# 10. Advanced Scheduling

---

## 🔹 Node Affinity

More flexible than nodeSelector

---

## 🔹 Taints & Tolerations

Allow DaemonSet to run on restricted nodes

```yaml
tolerations:
- key: "node-role.kubernetes.io/master"
  operator: Exists
  effect: NoSchedule
```

👉 Important for running on master/control-plane nodes

---

# 11. Update Strategy

---

## 🔹 Rolling Update (default)

```yaml
strategy:
  type: RollingUpdate
```

👉 Updates Pods node by node

---

## 🔹 OnDelete

```yaml
strategy:
  type: OnDelete
```

👉 Pods updated only when manually deleted

# 12. Real-World Example (Logging Agent)

```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: fluentd
spec:
  selector:
    matchLabels:
      app: fluentd
  template:
    metadata:
      labels:
        app: fluentd
    spec:
      containers:
      - name: fluentd
        image: fluentd:v1
        volumeMounts:
        - name: varlog
          mountPath: /var/log
      volumes:
      - name: varlog
        hostPath:
          path: /var/log
```

---

## What this does:

* Runs on every node
* Collects logs from `/var/log`
