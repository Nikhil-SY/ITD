Services are where Kubernetes networking finally “clicks.” Without Services, Pods are just isolated IPs that keep changing.

Let’s go **deep + practical + interview-ready**.

---

# 🚀 Kubernetes Services (Complete Guide)

---

# 1. What is a Service?

## Definition

A **Service** is an abstraction that exposes a set of Pods as a **stable network endpoint**.

---

## Problem it Solves

Pods:

* Have **dynamic IPs** ❌
* Can restart anytime ❌

Service:

* Provides **fixed IP / DNS** ✔️
* Load balances traffic ✔️

---

# 2. Key Concept

```text
Service → stable endpoint → routes to Pods
```

---

# 3. How Service Works Internally

1. Service created
2. Selector finds matching Pods
3. Endpoints created
4. Traffic load-balanced

---

# 4. Basic Service YAML

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 80
```

---

# 6. Types of Services (VERY IMPORTANT)

---

# 🔹 1. ClusterIP (Default)

## Definition

* Internal Service
* Accessible only inside cluster

---

## YAML

```yaml
apiVersion: v1
kind: Service
metadata:
  name: clusterip-svc
spec:
  type: ClusterIP
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 80
```

---

## Access

```text
http://clusterip:80
```

---

## Use Case

✔ Internal communication

---

# 🔹 2. NodePort

## Definition

Exposes Service on **Node IP + Port**

---

## YAML

```yaml
apiVersion: v1
kind: Service
metadata:
  name: nodeport-svc
spec:
  type: NodePort
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 80
    nodePort: 30007
```

---

## Access

```text
http://<NodeIP>:30007
```

---

## Range

```text
30000–32767
```

---

# 🔹 3. LoadBalancer

## Definition

Creates external Load Balancer (cloud)

---

## YAML

```yaml
apiVersion: v1
kind: Service
metadata:
  name: lb-svc
spec:
  type: LoadBalancer
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 80
```

---

## Use Case

✔ Production external access

---

# 🔹 4. ExternalName

## Definition

Maps Service to external DNS

---

## YAML

```yaml
apiVersion: v1
kind: Service
metadata:
  name: external-svc
spec:
  type: ExternalName
  externalName: google.com
```

---

## Use Case

✔ External dependency

---

# 9. Service Discovery (DNS)

---

## DNS Format

```text
<service-name>.<namespace>.svc.cluster.local
```

---

## Example

```text
my-service.default.svc.cluster.local
```

---

## Inside Pod

```bash
curl http://my-service
```

---

# 10. Endpoints (IMPORTANT)

---

Service creates:

```bash
kubectl get endpoints
```

---

## Example

```text
my-service → 10.244.0.5:80, 10.244.0.6:80
```

👉 These are Pod IPs

---

# 11. Labels & Selectors (IMPORTANT)

---

Service uses:

```yaml
selector:
  app: my-app
```

👉 Matches Pods:

```yaml
labels:
  app: my-app
```

---

# 🔥 RULE

```text
Service selector == Pod labels
```

---

# 12. Headless Service (ADVANCED)

---

## Definition

No cluster IP

```yaml
clusterIP: None
```

---

## Use Case

✔ Stateful apps (DB, Kafka)

---

## YAML

```yaml
apiVersion: v1
kind: Service
metadata:
  name: headless
spec:
  clusterIP: None
  selector:
    app: my-app
  ports:
  - port: 80
```

---

# 13. Load Balancing

---

Service distributes traffic:

* Round-robin (default)
* Across all Pods

---
