# 🚀 Accessing Application using ClusterIP (Complete Guide)

---

# 1. Key Concept (VERY IMPORTANT)

```text
ClusterIP → ONLY accessible inside Kubernetes cluster
```

👉 You **cannot access it directly from your laptop/browser**

---

# 2. Basic Setup Example

---

## 🔹 Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: app
        image: nginx
        ports:
        - containerPort: 80
```

---

## 🔹 Service (ClusterIP)

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  type: ClusterIP
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 80
```

---

# 3. Ways to Access ClusterIP Service

---

# 🔹 Method 1: From Another Pod (MOST COMMON)

---

## Step 1: Create a test pod

```bash
kubectl run test-pod --image=busybox -it --rm -- sh
```

---

## Step 2: Access Service

```bash
wget -qO- http://my-service
```

OR

```bash
curl http://my-service
```

---

## Flow

```text
Test Pod → Service → Backend Pods
```

---

# 🔹 Method 2: Using ClusterIP Address

---

## Get ClusterIP

```bash
kubectl get svc
```

Example:

```text
my-service   ClusterIP   10.96.45.12   80/TCP
```

---

## Access

```bash
curl http://10.96.45.12
```

---

👉 Still only works **inside cluster**

---

# 🔹 Method 3: Using DNS (BEST PRACTICE)

---

## DNS Name

```text
my-service
```

OR full DNS:

```text
my-service.default.svc.cluster.local
```

---

## Access

```bash
curl http://my-service
```

---

# 4. Real Flow (IMPORTANT)

```text
Client Pod
   ↓
Service DNS (my-service)
   ↓
ClusterIP (Virtual IP)
   ↓
kube-proxy
   ↓
Pod IPs (Load balanced)
```

---

# 5. Why Not Accessible from Outside?

---

ClusterIP:

* Private virtual IP
* Exists only inside cluster network

👉 No external routing

---

# 6. How to Access from Outside (Workarounds)

---

## 🔹 Option 1: Port Forward

```bash
kubectl port-forward svc/my-service 8080:80
```

Access in browser:

```text
http://localhost:8080
```

---

## 🔹 Option 2: Use NodePort

Change service:

```yaml
type: NodePort
```

---

## 🔹 Option 3: Use LoadBalancer / Ingress

Production approach

---

# 7. Debugging Steps (VERY IMPORTANT)

---

## Step 1: Check Service

```bash
kubectl get svc
```

---

## Step 2: Check Endpoints

```bash
kubectl get endpoints
```

👉 If empty:
❌ Selector mismatch

---

## Step 3: Check Pods

```bash
kubectl get pods --show-labels
```

---

## Step 4: Test inside Pod

```bash
kubectl exec -it <pod> -- curl my-service
```

---

# 8. Common Issues

---

❌ Selector mismatch
❌ Pods not running
❌ Wrong port/targetPort
❌ No endpoints
