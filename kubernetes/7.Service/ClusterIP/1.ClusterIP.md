# 🚀 ClusterIP Service (Complete Deep Dive)

---

# 1. What is ClusterIP?

## Definition

A **ClusterIP Service** exposes Pods **internally within the cluster** using a **stable virtual IP**.

---

## Key Idea

```text
ClusterIP → internal-only → stable IP → load balances Pods
```

---

# 2. Why ClusterIP?

Pods:

* Dynamic IP ❌
* Restart → new IP ❌

ClusterIP:

* Fixed virtual IP ✔️
* DNS name ✔️
* Load balancing ✔️

---

# 3. Default Service Type

👉 If you don’t specify type:

```yaml
type: ClusterIP
```

---

# 4. Basic YAML

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-clusterip
spec:
  type: ClusterIP
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 8080
```

---

# 5. YAML Fields Explained

---

## 🔹 selector (CRITICAL)

```yaml
selector:
  app: my-app
```

👉 Matches Pods:

```yaml
labels:
  app: my-app
```

---

## 🔹 ports

```yaml
ports:
- port: 80
  targetPort: 8080
```

---

### Meaning

| Field      | Meaning            |
| ---------- | ------------------ |
| port       | Service port       |
| targetPort | Pod container port |

---

# 🔥 Flow

```text
Pod A → Service:80 → Pod B:8080
```

---

# 6. How ClusterIP Works Internally (VERY IMPORTANT)

---

## Step-by-step

1. Service created
2. ClusterIP assigned (virtual IP)
3. kube-proxy configures routing
4. Endpoints mapped
5. Traffic load balanced

---

## Internal Flow

```text
Client Pod
   ↓
ClusterIP (Virtual IP)
   ↓
kube-proxy (iptables/ipvs)
   ↓
Pod IPs
```

---

# 7. ClusterIP is Virtual (IMPORTANT)

👉 It is NOT a real interface IP

* Exists in **iptables/IPVS rules**
* Managed by **kube-proxy**

---

# 8. Check ClusterIP

```bash
kubectl get svc
```

Example:

```text
NAME            TYPE        CLUSTER-IP     PORT
my-clusterip    ClusterIP   10.96.45.12    80/TCP
```

---

# 9. Accessing ClusterIP

---

## From inside cluster

```bash
curl http://my-clusterip
```

OR

```bash
curl http://10.96.45.12
```

---

## From outside cluster

❌ Not accessible

---

# 10. DNS Resolution (VERY IMPORTANT)

---

## Format

```text
<service-name>.<namespace>.svc.cluster.local
```

---

## Example

```text
my-clusterip.default.svc.cluster.local
```

---

## Inside Pod

```bash
curl http://my-clusterip
```

👉 Kubernetes DNS resolves it

---

# 11. Endpoints (BACKEND Pods)

---

Check:

```bash
kubectl get endpoints
```

Example:

```text
my-clusterip → 10.244.0.5:8080, 10.244.0.6:8080
```

---

👉 These are actual Pod IPs

---

# 12. Load Balancing

---

ClusterIP distributes traffic across Pods:

✔ Round-robin (default)
✔ Handled by kube-proxy

---

# 13. kube-proxy Role (IMPORTANT)

---

kube-proxy:

* Watches Services & Endpoints
* Programs iptables/IPVS rules

---

## Modes

* iptables (default)
* IPVS (high performance)

---

# 14. Example (Full Flow)

---

## Service

```yaml

  app: web
```

---

## Flow

```text
Pod1 (client)
   ↓
Service (ClusterIP)
   ↓

```

---

# 15. Headless Service vs ClusterIP

---

## ClusterIP

```yaml
clusterIP: 10.x.x.x
```

✔ Load balancing
✔ Single IP

---

## Headless

```yaml
clusterIP: None
```

✔ No load balancing
✔ Direct Pod IPs
