# Scenario: Control Kubernetes cluster from your local Ubuntu

Goal:
From your **Ubuntu laptop**, you want to connect securely to a Kubernetes cluster and run:

```bash
kubectl get pods
kubectl apply -f deployment.yaml
kubectl logs mypod
```

To do this, Kubernetes needs to know:

```text
1. WHO are you?        → User authentication
2. WHICH cluster?      → Cluster details
3. WHICH namespace?    → Default namespace
4. WHAT permissions?   → RBAC
```

All of this is managed through **kubeconfig** and **context**.

---

# Big Picture Flow

```text
Ubuntu Laptop
    |
    | kubectl
    |
    |---- kubeconfig (~/.kube/config)
              |
              |--- Cluster
              |--- User credentials
              |--- Context
    |
    v
Kubernetes API Server
    |
    |-- Authentication (Who are you?)
    |-- Authorization (RBAC)
    |
    v
Access granted/denied
```

# Step 2: Understand kubeconfig (`~/.kube/config`)

This file stores **everything needed to connect**.

Location:

```bash
cat ~/.kube/config
```

Typical structure:

```yaml
apiVersion: v1
kind: Config

clusters:
- name: prod-cluster
  cluster:
    server: https://10.0.0.5:6443
    certificate-authority-data: LS0...

users:
- name: nikhil
  user:
    client-certificate: /home/nikhil/.kube/nikhil.crt
    client-key: /home/nikhil/.kube/nikhil.key

contexts:
- name: nikhil-prod
  context:
    cluster: prod-cluster
    user: nikhil
    namespace: default

current-context: nikhil-prod
```

# Step 3: Understand the 3 core pieces

## A. Cluster

Defines **where kubectl should connect**.

```yaml
clusters:
- name: prod-cluster
  cluster:
    server: https://10.0.0.5:6443
```

### Meaning:

* `name` → friendly name
* `server` → Kubernetes API endpoint
* `6443` → default Kubernetes API port

Command to add cluster manually:

```bash
kubectl config set-cluster prod-cluster \
  --server=https://10.0.0.5:6443
```

### Command explanation:

* `kubectl config` → manage kubeconfig
* `set-cluster` → add/update cluster entry
* `prod-cluster` → cluster nickname
* `--server` → API server URL

---

## B. User (your identity)

Defines **who you are**.

For local Ubuntu access, commonly **certificate-based authentication**.

---

### Create private key

```bash
openssl genrsa -out nikhil.key 2048
```

Explanation:

* `openssl` → crypto tool
* `genrsa` → generate RSA key
* `-out nikhil.key` → output file
* `2048` → key size

Creates:

```text
nikhil.key
```

---

### Create CSR (Certificate Signing Request)

```bash
openssl req -new \
-key nikhil.key \
-out nikhil.csr \
-subj "/CN=nikhil"
```

Explanation:

* `req -new` → create CSR
* `-key` → use private key
* `-out` → CSR file
* `CN=nikhil` → username Kubernetes will see

---

### Send CSR to Kubernetes

First encode CSR:

```bash
cat nikhil.csr | base64 | tr -d '\n'
```

Explanation:

* `base64` → encode
* `tr -d '\n'` → remove newlines

Copy output.

---

### Create CSR YAML

```yaml
apiVersion: certificates.k8s.io/v1
kind: CertificateSigningRequest
metadata:
  name: nikhil-csr
spec:
  request: <PASTE_BASE64_CSR>
  signerName: kubernetes.io/kube-apiserver-client
  usages:
  - client auth
```

Apply:

```bash
kubectl apply -f csr.yaml
```

Approve:

```bash
kubectl certificate approve nikhil-csr
```

Download certificate:

```bash
kubectl get csr nikhil-csr \
-o jsonpath='{.status.certificate}' \
| base64 -d > nikhil.crt
```

Now you have:

```text
nikhil.key
nikhil.crt
```

---

## Add user to kubeconfig

```bash
kubectl config set-credentials nikhil \
  --client-certificate=nikhil.crt \
  --client-key=nikhil.key
```

### Explanation:

* `set-credentials` → create user entry
* `nikhil` → username in kubeconfig
* `--client-certificate` → public cert
* `--client-key` → private key

---

## C. Context

### What is context?

A **context = Cluster + User + Namespace**

Formula:

```text
Context = (Cluster + User + Namespace)
```

Example:

```yaml
context:
  cluster: prod-cluster
  user: nikhil
  namespace: dev
```

This tells kubectl:

```text
Connect to prod-cluster
Authenticate as nikhil
Use dev namespace by default
```

---

## Create context

```bash
kubectl config set-context nikhil-prod \
  --cluster=prod-cluster \
  --user=nikhil \
  --namespace=dev
```

Explanation:

* `set-context` → create context
* `nikhil-prod` → context name
* `--cluster` → which cluster
* `--user` → which user
* `--namespace` → default namespace

---

## Switch to context

```bash
kubectl config use-context nikhil-prod
```

Explanation:

* makes this your active context

Check:

```bash
kubectl config current-context
```

# Step 4: RBAC permission

Without RBAC, you may still get:

```text
Forbidden
```

Need role + binding.

---

## Create Role

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: dev
  name: developer-role
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get","list","watch"]
```

Apply:

```bash
kubectl apply -f role.yaml
```

---

## Bind role to user

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: nikhil-binding
  namespace: dev
subjects:
- kind: User
  name: nikhil
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: developer-role
  apiGroup: rbac.authorization.k8s.io
```

Apply:

```bash
kubectl apply -f binding.yaml
```

# Why context is important

Without context:

```bash
kubectl delete pod app
```

Could accidentally delete in **production**.

With context awareness:

```bash
kubectl config current-context
```

Always check before running commands.

# `kubectx` (Very useful)

`kubectx` makes context switching easier.

Instead of:

```bash
kubectl config use-context dev-context
```

Use:

```bash
kubectx dev-context
```

---

## Install kubectx on Ubuntu

Using Git:

```bash
sudo git clone https://github.com/ahmetb/kubectx /opt/kubectx
sudo ln -s /opt/kubectx/kubectx /usr/local/bin/kubectx
```

### Explanation:

* clone repository
* create symbolic link so command works globally

Check:

```bash
kubectx
```

---

## Usage of kubectx

### List contexts

```bash
kubectx
```

Example:

```text
dev-context
prod-context
test-context
```

---

### Switch context

```bash
kubectx prod-context
```

---

### Switch to previous context

```bash
kubectx -
```

Very useful.

# Interview-style quick summary

## What is kubeconfig?

Configuration file storing cluster, user, and context details.

---

## What is context?

```text
Context = Cluster + User + Namespace
```

Used to tell kubectl **where and how to connect**.

---

## How does authentication happen?

Using:

* Client certificates (`.crt + .key`)
* Token
* Cloud IAM

---

## How does authorization happen?

RBAC checks:

* Role
* RoleBinding

---

## Why use `kubectx`?

Quick context switching:

```bash
kubectx prod
kubectx dev
kubectx -
```

Much easier than full `kubectl config use-context`.
