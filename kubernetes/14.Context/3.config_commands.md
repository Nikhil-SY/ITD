## View

### `kubectl config view`

Print the full kubeconfig file.

```bash
# print full kubeconfig (sensitive data redacted)
kubectl config view

# show raw certs and tokens (unredacted)
kubectl config view --raw

# show only the active context config
kubectl config view --minify

# output as json
kubectl config view -o json

# extract api server url
kubectl config view --minify -o jsonpath='{.clusters[0].cluster.server}'
# output: https://ABCD1234.gr7.ap-south-1.eks.amazonaws.com

# extract current namespace
kubectl config view --minify -o jsonpath='{.contexts[0].context.namespace}'
# output: default

# show config from a specific file
kubectl config view --kubeconfig=/path/to/other-config
```

---

### `kubectl config get-contexts`

List all contexts with cluster, user, and namespace.

```bash
# list all contexts
kubectl config get-contexts
# CURRENT   NAME          CLUSTER       AUTHINFO    NAMESPACE
# *         dec-2025      my-cluster    nikhil      default
#           prod          prod-k8s      admin       production
#           dev           dev-k8s       nikhil      staging

# list context names only (for scripting)
kubectl config get-contexts -o name
# dec-2025
# prod
# dev

# inspect a specific context
kubectl config get-contexts dec-2025
```

---

### `kubectl config current-context`

Print just the name of the currently active context.

```bash
kubectl config current-context
# dec-2025

# use in a shell script
CTX=$(kubectl config current-context)
echo "Deploying to: $CTX"
```

---

### `kubectl config get-clusters`

List all cluster entries registered in kubeconfig.

```bash
kubectl config get-clusters
# NAME
# my-cluster
# prod-k8s
# dev-k8s
```

---

### `kubectl config get-users`

List all user credential entries.

```bash
kubectl config get-users
# NAME
# nikhil
# admin
# service-account-readonly
```

## Switch / Set

### `kubectl config use-context`

Switch the active context. All subsequent kubectl commands target the new cluster/user/namespace.

```bash
# switch to a different cluster
kubectl config use-context prod
# Switched to context "prod".

# switch back
kubectl config use-context dec-2025

# verify the switch
kubectl config current-context
# dec-2025

# run one command in a different context without switching permanently
kubectl --context=prod get nodes
```

> **Tip:** Install [kubectx](https://github.com/ahmetb/kubectx) for faster switching with tab completion: `kubectx prod`

---

### `kubectl config set-context --current`

Change the default namespace for the active context.

```bash
# set default namespace to production
kubectl config set-context --current --namespace=production
# Context "dec-2025" modified.

# verify
kubectl config view --minify | grep namespace
#     namespace: production

# reset back to default
kubectl config set-context --current --namespace=default

# one-off namespace override without changing context
kubectl -n staging get pods
```

> **Tip:** Install [kubens](https://github.com/ahmetb/kubectx) for faster namespace switching: `kubens production`

---

### `kubectl config set-context`

Create a new context or update an existing one.

```bash
# create a new context
kubectl config set-context staging-ctx \
  --cluster=dev-k8s \
  --user=nikhil \
  --namespace=staging
# Context "staging-ctx" created.

# update only the user on existing context
kubectl config set-context dec-2025 --user=admin

# update only the namespace
kubectl config set-context dec-2025 --namespace=kube-system

# activate it
kubectl config use-context staging-ctx
```

---

### `kubectl config rename-context`

Rename an existing context. Especially useful for long EKS ARN-based names.

```bash
# rename an unwieldy EKS context name
kubectl config rename-context \
  arn:aws:eks:ap-south-1:123456789012:cluster/my-eks-cluster \
  prod-eks
# Context "arn:aws:eks:..." renamed to "prod-eks".

# rename for clarity
kubectl config rename-context dec-2025 personal-dev
```

## Create

### `kubectl config set-cluster`

Add or update a cluster entry in kubeconfig.

```bash
# add cluster with ca cert file
kubectl config set-cluster my-cluster \
  --server=https://1.2.3.4:6443 \
  --certificate-authority=/etc/kubernetes/ca.crt

# embed ca cert data inline (no external file reference)
kubectl config set-cluster my-cluster \
  --server=https://1.2.3.4:6443 \
  --certificate-authority=/etc/kubernetes/ca.crt \
  --embed-certs=true

# skip tls verify (dev/local only — never in production)
kubectl config set-cluster local-cluster \
  --server=https://localhost:6443 \
  --insecure-skip-tls-verify=true

# update only the server url
kubectl config set-cluster my-cluster \
  --server=https://5.6.7.8:6443
```

> **Tip:** For EKS, use `aws eks update-kubeconfig --name <cluster> --region <region>` — it runs set-cluster, set-credentials, and set-context all in one step.

---

### `kubectl config set-credentials`

Add or update a user credential entry.

```bash
# token-based (service account)
kubectl config set-credentials sa-user \
  --token=eyJhbGciOiJSUzI1NiIsInR5...

# client certificate
kubectl config set-credentials nikhil \
  --client-certificate=/path/to/nikhil.crt \
  --client-key=/path/to/nikhil.key

# embed cert data inline
kubectl config set-credentials nikhil \
  --client-certificate=/path/to/nikhil.crt \
  --client-key=/path/to/nikhil.key \
  --embed-certs=true

# exec plugin — EKS with aws cli
kubectl config set-credentials eks-user \
  --exec-command=aws \
  --exec-arg=eks \
  --exec-arg=get-token \
  --exec-arg=--cluster-name=my-eks-cluster \
  --exec-api-version=client.authentication.k8s.io/v1beta1
```

## Delete

### `kubectl config delete-context`

Remove a context entry from kubeconfig.

```bash
kubectl config delete-context old-context
# deleted context old-context from /home/nikhil/.kube/config

# delete multiple contexts with a shell loop
for ctx in old-dev old-staging; do
  kubectl config delete-context $ctx
done

# verify it is gone
kubectl config get-contexts
```

> **Warning:** If you delete your only admin context you may lose cluster access. Keep a backup: `cp ~/.kube/config ~/.kube/config.bak`

---

### `kubectl config delete-cluster`

Remove a cluster entry. Any contexts pointing to this cluster will break until updated.

```bash
kubectl config delete-cluster old-cluster
# deleted cluster old-cluster from /home/nikhil/.kube/config
```

---

### `kubectl config delete-user`

Remove a user credential entry.

```bash
kubectl config delete-user service-account-readonly
# deleted user service-account-readonly from /home/nikhil/.kube/config
```

---

### `kubectl config unset`

Remove any specific field using dot-path notation. More surgical than the delete commands.

```bash
# remove a user entry
kubectl config unset users.nikhil

# remove a cluster entry
kubectl config unset clusters.my-cluster

# clear namespace on a specific context
kubectl config unset contexts.dec-2025.namespace

# remove token from a user
kubectl config unset users.sa-user.token
```

## Merge

### `KUBECONFIG` environment variable

Merge multiple kubeconfig files by setting `KUBECONFIG` as a colon-separated list. kubectl merges them in memory at runtime.

```bash
# temporarily merge two configs (current shell session only)
export KUBECONFIG=~/.kube/config:~/.kube/prod-config
kubectl config get-contexts   # shows contexts from both files

# merge permanently into one file
KUBECONFIG=~/.kube/config:~/.kube/prod-config \
  kubectl config view --flatten > /tmp/merged
mv /tmp/merged ~/.kube/config

# add eks cluster (auto-merges into ~/.kube/config)
aws eks update-kubeconfig \
  --name my-eks-cluster \
  --region ap-south-1
# Added new context arn:aws:eks:ap-south-1:123456789012:cluster/my-eks-cluster

# add eks with a custom short alias
aws eks update-kubeconfig \
  --name my-eks-cluster \
  --region ap-south-1 \
  --alias prod-eks

# use a different kubeconfig for one command only
kubectl --kubeconfig=/path/to/other-config get pods

# add to ~/.bashrc or ~/.zshrc for persistence
export KUBECONFIG=~/.kube/config:~/.kube/work-config:~/.kube/home-config
```

> **Tip:** `kubectl config view --flatten` merges all files into a single valid kubeconfig — ideal before sharing configs or committing to a repo (after removing secrets).

## Debug / Auth

### `kubectl auth whoami`

Show exactly who Kubernetes thinks you are. Run this first when debugging any `Forbidden` error.

```bash
kubectl auth whoami
# ATTRIBUTE   VALUE
# Username    nikhil
# Groups      [system:authenticated]

# check identity in a different context
kubectl --context=prod auth whoami

# check identity scoped to a namespace
kubectl auth whoami -n production
```

> **Tip:** If this shows `system:serviceaccount:default:something` — your kubeconfig user is set to a service account token, not your personal credentials. This causes Forbidden errors when applying RBAC.

---

### `kubectl auth can-i`

Test whether the current user (or an impersonated identity) has permission to perform an action.

```bash
# check your own permission
kubectl auth can-i create deployments -n production
# yes

# check a permission you do not have
kubectl auth can-i delete secrets
# no

# check as another user
kubectl auth can-i list pods --as=nikhil -n default
# yes

# check as a service account
kubectl auth can-i delete secrets \
  --as=system:serviceaccount:default:service-account-readonly
# no

# list ALL permissions for your current user in a namespace
kubectl auth can-i --list -n default

# list all permissions for a specific service account
kubectl auth can-i --list \
  --as=system:serviceaccount:default:service-account-readonly \
  -n default

# check a subresource (e.g. pod logs)
kubectl auth can-i get pods/log -n default
```

---

### `kubectl config set`

Low-level command to set any kubeconfig field using dot-path notation.

```bash
# set proxy url on a cluster
kubectl config set clusters.my-cluster.proxy-url http://proxy:8080

# set a context field directly
kubectl config set contexts.dec-2025.namespace kube-system

# update server url directly
kubectl config set clusters.my-cluster.server https://new-ip:6443
```

## Quick reference cheatsheet

| Command | What it does |
|---|---|
| `kubectl config view` | Print full kubeconfig |
| `kubectl config view --minify` | Print only active context config |
| `kubectl config get-contexts` | List all contexts |
| `kubectl config current-context` | Show active context name |
| `kubectl config use-context <name>` | Switch active context |
| `kubectl config set-context --current --namespace=<ns>` | Change default namespace |
| `kubectl config rename-context <old> <new>` | Rename a context |
| `kubectl config set-cluster <name> --server=<url>` | Add a cluster |
| `kubectl config set-credentials <name> --token=<token>` | Add a user |
| `kubectl config set-context <name> --cluster=<c> --user=<u>` | Create a context |
| `kubectl config delete-context <name>` | Remove a context |
| `kubectl config delete-cluster <name>` | Remove a cluster |
| `kubectl config delete-user <name>` | Remove a user |
| `kubectl config unset <dot.path>` | Remove any specific field |
| `kubectl auth whoami` | Show your K8s identity |
| `kubectl auth can-i <verb> <resource>` | Check a permission |
| `kubectl auth can-i --list -n <ns>` | List all your permissions |

## Useful aliases

Add these to your `~/.bashrc` or `~/.zshrc`:

```bash
alias kctx='kubectl config use-context'
alias kns='kubectl config set-context --current --namespace'
alias kwho='kubectl auth whoami'
alias kctxs='kubectl config get-contexts'

# usage
kctx prod           # switch to prod context
kns staging         # switch to staging namespace
kwho                # check identity
kctxs               # list all contexts
```
