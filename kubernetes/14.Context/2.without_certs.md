# Scenario: Control Kubernetes cluster from local Ubuntu **without certificates**

If you **don’t want client certificates (`.crt/.key`)**, the most common way is:

```text
Local Ubuntu → kubectl → kubeconfig → ServiceAccount Token → Kubernetes API Server
```

This is very common for:

* Lab / local clusters
* Temporary admin access
* Automation scripts
* Testing RBAC

Here, instead of a **User + cert**, you use a **ServiceAccount + token**.

---

# Big picture

```text
1. Create ServiceAccount in cluster
2. Create Role / ClusterRole
3. Create RoleBinding / ClusterRoleBinding
4. Generate token for ServiceAccount
5. Add cluster info to kubeconfig
6. Add token as credentials
7. Create context
8. Use kubectl
```

---

# Step 1: Create ServiceAccount

This creates an identity inside Kubernetes.

### `sa.yaml`

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: nikhil-sa
  namespace: dev
```

Apply:

```bash
kubectl apply -f sa.yaml
```

Check:

```bash
kubectl get sa -n dev
```

Output:

```text
NAME        SECRETS   AGE
nikhil-sa   0         5s
```

### Explanation

* `kind: ServiceAccount` → creates Kubernetes identity
* `name: nikhil-sa` → service account name
* `namespace: dev` → exists only in `dev`

---

# Step 2: Create permissions (Role)

Example: allow pod access.

### `role.yaml`

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
  namespace: dev
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "list", "watch"]
```

Apply:

```bash
kubectl apply -f role.yaml
```

---

# Step 3: Bind role to ServiceAccount

### `binding.yaml`

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: nikhil-sa-binding
  namespace: dev
subjects:
- kind: ServiceAccount
  name: nikhil-sa
  namespace: dev
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

Apply:

```bash
kubectl apply -f binding.yaml
```

---

# Step 4: Generate token

In modern Kubernetes (v1.24+):

```bash
kubectl create token nikhil-sa -n dev
```

Example output:

```text
eyJhbGciOiJSUzI1NiIsImtpZCI6...
```

This is your **authentication token**.

Save it:

```bash
TOKEN=$(kubectl create token nikhil-sa -n dev)
echo $TOKEN
```

---

# Step 5: Get cluster details

You need the Kubernetes API server URL.

Run:

```bash
kubectl config view --minify
```

Example:

```yaml
clusters:
- cluster:
    server: https://10.0.0.5:6443
```

Copy:

```text
https://10.0.0.5:6443
```

---

## Get cluster CA certificate

Needed so kubectl trusts the API server.

Export:

```bash
kubectl config view --raw \
-o jsonpath='{.clusters[0].cluster.certificate-authority-data}' \
| base64 -d > ca.crt
```

This creates:

```text
ca.crt
```

---

# Step 6: Add cluster to kubeconfig

```bash
kubectl config set-cluster my-cluster \
  --server=https://10.0.0.5:6443 \
  --certificate-authority=ca.crt
```

### Explanation

* `set-cluster` → create cluster entry
* `my-cluster` → nickname
* `--server` → API endpoint
* `--certificate-authority` → trust certificate

---

# Step 7: Add token as credentials

```bash
kubectl config set-credentials nikhil-token \
  --token=$TOKEN
```

### Explanation

* `set-credentials` → add user credentials
* `nikhil-token` → credential name
* `--token` → use token instead of certs

---

# Step 8: Create context

Remember:

```text
Context = Cluster + Credentials + Namespace
```

Create it:

```bash
kubectl config set-context nikhil-dev \
  --cluster=my-cluster \
  --user=nikhil-token \
  --namespace=dev
```

---

# Step 9: Use context

```bash
kubectl config use-context nikhil-dev
```

Check:

```bash
kubectl config current-context
```

Output:

```text
nikhil-dev
```

---

# Step 10: Test access

Try:

```bash
kubectl get pods
```

Or explicitly verify RBAC:

```bash
kubectl auth can-i list pods
```

Expected:

```text
yes
```

# Practical shortcut (single kubeconfig file)

You can even create a separate kubeconfig:

```bash
kubectl config set-cluster my-cluster \
  --server=https://10.0.0.5:6443 \
  --certificate-authority=ca.crt \
  --kubeconfig=nikhil-kubeconfig
```

```bash
kubectl config set-credentials nikhil-token \
  --token=$TOKEN \
  --kubeconfig=nikhil-kubeconfig
```

```bash
kubectl config set-context nikhil-dev \
  --cluster=my-cluster \
  --user=nikhil-token \
  --namespace=dev \
  --kubeconfig=nikhil-kubeconfig
```

Use it:

```bash
kubectl --kubeconfig=nikhil-kubeconfig get pods
```

Useful when managing multiple clusters.

# Interview quick answer

## How to access Kubernetes without certs?

Use **ServiceAccount token authentication**:

* Create ServiceAccount
* Assign RBAC permissions
* Generate token
* Add token in kubeconfig
* Create context
* Use kubectl

---

## Why use this?

Simpler than certificate-based auth, especially for:

* Automation
* CI/CD
* Temporary access
* Local testing

---

## Important note

For **human users in production**, prefer:

* OpenID Connect / Single Sign-On
* Cloud IAM (Amazon Web Services / Microsoft Azure / Google Cloud)

For **pods/tools/scripts**, ServiceAccount tokens are ideal.

Here's the complete guide from scratch, with the TLS fix baked in.

---

## Prerequisites

- 3 EC2 instances (Ubuntu 22.04) — 1 master, 2 workers
- Minimum **t2.medium** (2 CPU, 2GB RAM) — kubeadm won't run on less
- Port **6443** open in the master's security group for your local IP
- SSH access to all 3 nodes

---

## Part 1: On ALL 3 nodes (master + both workers)

### 1. Disable swap
```bash
sudo swapoff -a
sudo sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab
```

### 2. Load kernel modules
```bash
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF

sudo modprobe overlay
sudo modprobe br_netfilter
```

### 3. Set sysctl parameters
```bash
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

sudo sysctl --system
```

### 4. Install containerd
```bash
sudo apt-get update
sudo apt-get install -y containerd

sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml

# Enable SystemdCgroup (required for kubeadm)
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml

sudo systemctl restart containerd
sudo systemctl enable containerd
```

### 5. Install kubeadm, kubelet, kubectl
```bash
sudo apt-get update
sudo apt-get install -y apt-transport-https ca-certificates curl

curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.29/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.29/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list

sudo apt-get update
sudo apt-get install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl
```

---

## Part 2: On the MASTER node only

### 6. Initialize the cluster with public IP as SAN
This is the key step that avoids the TLS error later — pass your master's **public IP** via `--apiserver-cert-extra-sans`:

```bash
sudo kubeadm init \
  --apiserver-cert-extra-sans=<master-public-ip> \
  --pod-network-cidr=192.168.0.0/16
```

> `--apiserver-cert-extra-sans` adds your public IP to the TLS cert at creation time, so no cert regeneration is needed later.
> `--pod-network-cidr=192.168.0.0/16` is for Calico (used in step 8). Use `10.244.0.0/16` if you prefer Flannel.

### 7. Set up kubeconfig on the master
```bash
mkdir -p $HOME/.kube
sudo cp /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
```

### 8. Install a pod network (Calico)
```bash
kubectl apply -f https://raw.githubusercontent.com/projectcalico/calico/v3.27.0/manifests/calico.yaml
```

Wait ~60 seconds, then verify all control plane pods are running:
```bash
kubectl get pods -n kube-system
```

### 9. Save the join command
`kubeadm init` printed a join command at the end. Copy it — looks like:
```bash
kubeadm join 172.31.x.x:6443 --token <token> --discovery-token-ca-cert-hash sha256:<hash>
```

If you lost it, regenerate:
```bash
kubeadm token create --print-join-command
```

---

## Part 3: On BOTH worker nodes

### 10. Join the cluster
Run the join command you saved (with `sudo`):
```bash
sudo kubeadm join 172.31.x.x:6443 --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash>
```

---

## Part 4: On your LOCAL Ubuntu machine

### 11. Install kubectl
```bash
sudo apt-get update
sudo apt-get install -y apt-transport-https ca-certificates curl

curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.29/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.29/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list

sudo apt-get update
sudo apt-get install -y kubectl
```

### 12. Copy kubeconfig from master
```bash
mkdir -p ~/.kube
scp user@<master-public-ip>:/etc/kubernetes/admin.conf ~/.kube/config
```

### 13. Point kubectl to the public IP
The kubeconfig has the private IP baked in — update it to the public IP:
```bash
kubectl config set-cluster kubernetes \
  --server=https://<master-public-ip>:6443
```

### 14. Verify everything works
```bash
kubectl get nodes
```

Expected output:
```
NAME       STATUS   ROLES           AGE   VERSION
master     Ready    control-plane   5m    v1.29.x
worker-1   Ready    <none>          3m    v1.29.x
worker-2   Ready    <none>          3m    v1.29.x
```

---

## What made it work cleanly (no TLS error)

| What | Why |
|---|---|
| `--apiserver-cert-extra-sans=<public-ip>` | Adds public IP to the TLS cert at init time |
| `kubectl config set-cluster --server=<public-ip>` | Points kubectl to the public IP |
| No `--insecure-skip-tls-verify` needed | Cert already covers the public IP |
