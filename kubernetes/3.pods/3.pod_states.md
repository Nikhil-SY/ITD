## Pod States (Phases)

---

### 1. Pending
Pod is accepted by Kubernetes but **not yet running**.

Two reasons this happens:
- **Scheduler hasn't assigned a node yet** — still evaluating
- **Image is being pulled** — node is downloading the container image

```
You apply YAML → etcd stores it → Phase: Pending
```

---

### 2. Running
Pod has been assigned to a node and **at least one container is running**.

Doesn't mean everything is healthy — just means containers are up.

```
Kubelet started containers → Phase: Running
```

---

### 3. Succeeded
All containers in the pod **finished successfully** (exit code 0).

Common for batch jobs or one-time tasks, not long-running services.

```yaml
# Example: a pod that runs a script and exits
restartPolicy: Never
```

---

### 4. Failed
All containers have stopped and **at least one exited with an error** (non-zero exit code).

```
Container crashed / script failed → Phase: Failed
```

---

### 5. Unknown
API Server **can't get the pod's status** from the node.

Usually means the node itself is down or the Kubelet stopped responding.

---

## Phase Flow Diagram

```
                    ┌─────────┐
         apply YAML │ Pending │
                    └────┬────┘
                         │ node assigned + containers start
                    ┌────▼────┐
                    │ Running │
                    └────┬────┘
              ┌──────────┴──────────┐
              │                     │
       ┌──────▼──────┐       ┌──────▼──────┐
       │  Succeeded  │       │   Failed    │
       │  (exit 0)   │       │  (exit !=0) │
       └─────────────┘       └─────────────┘

   Node unreachable → Unknown
```

## Container States (inside a pod)

The pod phase is high level. Each **container inside** also has its own state:

| State | Meaning |
|---|---|
| **Waiting** | Pulling image, or waiting to start |
| **Running** | Container is executing |
| **Terminated** | Container finished or crashed |

You can see this with:
```
kubectl describe pod <pod-name>
```

---

## Common Real-World Scenarios

| Situation | State you'll see |
|---|---|
| Image name is wrong | `Pending` → `ErrImagePull` |
| Not enough CPU/memory on any node | Stuck in `Pending` |
| App crashes on startup | `Running` → `CrashLoopBackOff` |
| Node goes down | `Unknown` |
| Completed batch job | `Succeeded` |

---

### CrashLoopBackOff — worth knowing

This isn't an official phase but you'll see it constantly. It means:
- Container starts → crashes → Kubernetes restarts it → crashes again
- Kubernetes adds a backoff delay between restarts (10s, 20s, 40s...)

```
kubectl logs <pod-name>    ← check why it's crashing
```
